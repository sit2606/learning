## 🏗️ Объектно-ориентированное проектирование (повторение)

### Наследование в диаграммах классов
```
Ключевое проверочное слово: «является»
- Администратор ЯВЛЯЕТСЯ пользователем ✓
- Студент ЯВЛЯЕТСЯ пользователем ✓
- Профиль ЯВЛЯЕТСЯ пользователем ✗ (это ассоциация, а не наследование)
```

### Типы отношений между классами

| Отношение | Обозначение | Смысл | Пример |
|-----------|-------------|-------|--------|
| **Наследование** | ▽→ (белый треугольник) | «является», расширение функционала | Студент → Пользователь |
| **Ассоциация** | → (простая стрелка) | связь между объектами | Пользователь → Профиль |
| **Агрегация** | ◇→ (ромб) | «часть целого», слабая связь | Заказ ◇→ Товар |
| **Композиция** | ◆→ (закрашенный ромб) | «часть целого», сильная связь | Дом ◆→ Комната |

### Пример кода на C++ (демонстрация ООП)
```cpp
// Класс Point (точка)
class Point {
private:
    double x, y;
public:
    Point() : x(0), y(0) {} // конструктор по умолчанию
    Point(double x, double y) : x(x), y(y) {} // параметризованный
    double distanceTo(Point* other); // метод расчёта расстояния
};

// Наследование: Point3D наследуется от Point
class Point3D : public Point {
private:
    double z; // дополнительное свойство
public:
    double distance3D(Point3D* other); // метод для 3D
};

// Ассоциация: Circle содержит две точки
class Circle {
private:
    Point* p1, *p2;
public:
    double calculateArea(); // делегирует расчёт точкам
};
```

**Ключевые принципы:**
- 🔹 Наследуются все свойства и методы базового класса
- 🔹 Конструкторы вызываются автоматически при создании объекта
- 🔹 `new` выделяет память в куче (heap), ссылка хранится в стеке
- 🔹 Полиморфизм: объекты наследников могут использовать методы базового класса

## 📊 Диаграммы UML

### Диаграмма состояний (State Diagram)
**Назначение:** отображает возможные состояния объекта и переходы между ними

**Основные элементы:**
- ⚫ **Состояние** — устойчивая ситуация (овал/прямоугольник)
- ➡️ **Переход** — триггерное событие (стрелка с условием)
- ● **Начало** / ◉ **Конец** — точки входа/выхода

**Пример: состояние заказа**
```
[Оформление] → (оформлен) → [Проверка] → (есть в наличии) → [Оплата]
                                    ↓
                              (нет в наличии)
                                    ↓
                              [Ожидание] → (товар прибыл) → [Доставка]
```

**Правила конечного автомата:**
1. Конечное число состояний
2. Объект находится только в одном состоянии в момент времени
3. Нет изолированных состояний (все достижимы)
4. Переходы мгновенны относительно времени пребывания в состоянии

### Диаграмма деятельности (Activity Diagram)
**Назначение:** отображает алгоритмическую логику, последовательность действий

**Основные элементы:**
- ▭ **Действие** — прямоугольник с закруглёнными углами
- ◇ **Ветвление** — ромб (if/else)
- ═▌ **Распараллеливание** / ═▌**Слияние** — горизонтальные полосы
- ➡️ **Поток управления** — стрелки

**Пример: оплата заказа**
```
[Получение заказа]
        ↓
    ═════════  (распараллеливание)
    ↓         ↓
[Проверка]  [Оформление]
[платежа]   [менеджером]
    ↓         ↓
    ═════════  (слияние)
        ↓
    ◇ <срочная?>
   /           \
[Обычная]    [Экспресс]
[доставка]   [доставка]
   \           /
    ═════════
        ↓
[Заказ выполнен]
```

**Дорожки (Swimlanes):** визуальное разделение по отделам/ролям:
```
| Отдел заказов | Отдел доставки | Бухгалтерия |
|---------------|----------------|-------------|
| Приём заказа  |                |             |
|               | Проверка склада|             |
|               | Отгрузка       | Проверка оплаты|
```

## 🤖 Введение в генеративный ИИ и LLM

### Что такое генеративный ИИ?
> Система машинного обучения, способная создавать новые уникальные данные, похожие на обучающую выборку (текст, код, изображения, музыка).

### Эволюция ИИ
```
1990-е: Символьный ИИ → экспертные системы, чат-боты по шаблонам
2000-е: Классическое МО → SVM, деревья решений, нейросети
2017+: Трансформеры → Attention-механизм, параллельная обработка
2020+: LLM (GPT, Gigachat) → генерация текста, кода, мультимодальность
```

### Ключевые концепции

| Термин | Описание |
|--------|----------|
| **LLM** (Large Language Model) | Большая языковая модель с миллиардами параметров |
| **Трансформер** | Архитектура с механизмом внимания (attention) для обработки последовательностей |
| **Промтинг** | Искусство составления эффективных запросов к ИИ |
| **ИИ-агент** | Специализированная «личность» на базе LLM для выполнения задач |
| **RAG** (Retrieval-Augmented Generation) | Поиск + генерация: обогащение ответов внешними данными |
| **Мультимодальность** | Работа с текстом, изображением, аудио, видео одновременно |

### Практическое применение промтинга
**Структура эффективного запроса:**
```
1. Роль: «Ты эксперт в области...»
2. Задача: «Разработай структуру курса...»
3. Контекст: «Для студентов 3 курса бакалавриата...»
4. Формат: «Ответ в виде: 1) план, 2) литература, 3) вопросы»
5. Ограничения: «Ссылки только на актуальные нормативные акты»
```

**Пример мультиагентного сценария:**
```
🎓 Преподаватель: формулирует учебные цели
🔍 Исследователь: ищет актуальные источники
✍️ Автор: пишет контент курса
🧪 Тестировщик: проверяет задания на корректность
→ Все агенты «общаются» внутри одной LLM
```

### ⚠️ Важные предостережения
- 🔸 **Галлюцинации**: ИИ может генерировать правдоподобную, но неверную информацию
- 🔸 **Проверка обязательна**: любой код/ответ нужно тестировать и верифицировать
- 🔸 **Данные — основа качества**: «мусор на входе = мусор на выходе»
- 🔸 **Контекст имеет значение**: устаревшие знания модели (обучение до определённой даты)

### Этические и практические аспекты
```
✅ ИИ — помощник, а не замена разработчика
✅ Повышение абстракции: от написания кода → к формулировке требований
✅ Новые возможности: автоматизация рутины, ускорение прототипирования
⚠️ Риск: зависимость от провайдеров, вопросы приватности, авторского права
```
