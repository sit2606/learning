## ⚙️ Алгоритмы и процедурная парадигма

### Что такое алгоритм?
- Точное предписание исполнителю выполнить последовательность действий для получения результата
- **Свойства алгоритма**:
  1. **Дискретность** — разбит на отдельные шаги
  2. **Конечность** — завершается за конечное число шагов
  3. **Определённость** — одинаковые входные данные → одинаковый результат
  4. **Результативность** — приводит к требуемому результату
  5. **Массовость** — применим к целому классу задач
  6. **Эффективность** — оптимальное использование времени и ресурсов

### Виды алгоритмов
| Тип | Характеристика | Пример |
|-----|---------------|--------|
| **Детерминированный** | Чёткая последовательность, предсказуемый результат | Расчёт площади окружности |
| **Вероятностный** | Содержит элементы случайности | Генерация случайных чисел |
| **Эвристический** | Решение на основе опыта, без гарантированного оптимума | Распознавание образов нейросетью |

## 🔧 Процедурное программирование: функции и процедуры

### Ключевые понятия
```
Подпрограмма — именованный блок кода, вызываемый по имени
├─ Функция — возвращает значение (return)
├─ Процедура — выполняет действия, не возвращает значение (void)
└─ Метод — функция/процедура внутри класса (ООП)
```

### Пример на C++
```cpp
// Функция: возвращает результат
short myDiv(short a, short b) {
    return a / b;  // возврат значения
}

// Процедура: только действие
void myPrint(short x) {
    cout << "Результат: " << x << endl;  // вывод, но нет return
}
```

### Рекомендации по проектированию функций
✅ Выполнять одну логическую операцию  
✅ Иметь содержательное имя  
✅ Быть компактной  
✅ Обрабатывать ошибки, а не «падать»  
✅ Минимизировать количество параметров (но не в ущерб читаемости)

### 2. Ветвление (выбор)
#### Бинарный выбор: `if-else`
```cpp
if (x > 0 && y > 0) {
    cout << "I четверть";
} else if (x < 0 && y > 0) {
    cout << "II четверть";
} // ... и т.д.
```

#### Множественный выбор: `switch-case`
```cpp
switch (operation) {
    case "+": result = a + b; break;
    case "-": result = a - b; break;
    case "*": result = a * b; break;
    case "/": 
        if (b != 0) result = a / b;
        else error = true;
        break;
    default: error = true;
}
```

## 🗂️ Методология SADT / IDEF0

### Назначение
Инструмент **структурного анализа и проектирования** для декомпозиции сложных систем на функциональные модули.

### Элементы диаграммы
```
        ┌─────────────────┐
Управление│                 │Выход
    ─────►│    ПРОЦЕСС     │────►
        │                 │
Механизм│                 │Вызов
    ─────►│                 │────►
        └─────────────────┘
```

| Стрелка | Направление | Содержание |
|---------|-------------|------------|
| **Вход** | Слева → | Данные/материалы для обработки |
| **Выход** | → Справа | Результаты процесса |
| **Управление** | ↓ Сверху | Правила, законы, договоры, нормативы |
| **Механизм** | ↑ Снизу | Ресурсы: люди, оборудование, ПО |
| **Вызов** | →→ | Передача управления внешней системе (банк, 1С) |

### Уровни декомпозиции
1. **Контекстная диаграмма (А-0)** — система как один блок
2. **Диаграмма декомпозиции 1-го уровня (А0)** — 3–6 основных подпроцессов
3. **Диаграммы 2-го уровня (А1, А2...)** — детализация отдельных блоков

> ⚠️ **Важно!** Не теряйте стрелки при декомпозиции: все входы/выходы/управления должны найти отражение на нижних уровнях.
