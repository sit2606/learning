## 🔁 Повторение: «Воронка проектирования»

```
Предметная область 
       ↓
Логическая модель данных (независима от СУБД)
       ↓
Физическая модель данных (реализация в конкретной СУБД)
```

### Логическая модель
- Описывает сущности, их атрибуты и взаимосвязи
- Использует ER-диаграммы (Entity-Relationship)
- Применяет нормализацию (цель — 3НФ)
- **Не привязана к конкретной СУБД**

### Физическая модель
- Реализация логической модели средствами СУБД
- Отношения → таблицы, атрибуты → столбцы
- Домены → типы данных
- Ограничения → индексы, CHECK, FK, PK, триггеры

## 🗂️ Файловая структура PostgreSQL

### Основной каталог: `PGDATA`
```
PGDATA/
├── base/              # Пользовательские базы данных (по OID)
├── global/            # Общие системные каталоги
├── pg_wal/            # Журнал предзаписи (WAL)
├── pg_tblspc/         # Ссылки на табличные пространства
├── pg_stat/           # Статистика
├── postgresql.conf    # Основной конфиг
├── pg_hba.conf        # Настройки аутентификации
└── ...
```

### Хранение объектов
- Каждая БД → подкаталог в `base/` с именем = **OID** (Object Identifier)
- Каждая таблица/индекс → отдельный файл с именем = OID отношения
- Дополнительные файлы:
  - `OID_fsm` — Free Space Map (карта свободного места)
  - `OID_vm` — Visibility Map (карта видимости для MVCC)
  - `OID_init` — для нежурналируемых таблиц (UNLOGGED)

### Страницы данных
- Минимальная единица хранения: **8 КБ** (по умолчанию)
- Структура страницы:
  ```
  [Заголовок] [Указатели на кортежи] [Свободное место] [Кортежи] [Служебная информация]
  ```
- **TOAST-таблицы**: автоматически создаются для хранения больших значений, не помещающихся в страницу

## 📜 Журнал предзаписи (WAL — Write-Ahead Log)

### Принцип работы
```
1. Изменение → запись в WAL
2. Подтверждение транзакции после синхронизации WAL на диск
3. Асинхронная запись изменений в файлы данных
4. При сбое: восстановление из WAL
```

### Преимущества
- ✅ Меньше операций записи на диск (только WAL)
- ✅ Последовательная запись → высокая производительность
- ✅ Поддержка Point-in-Time Recovery
- ✅ Онлайн-резервное копирование

## 🗃️ Табличные пространства (Tablespaces)

### Зачем нужны?
| Проблема | Решение через tablespaces |
|----------|---------------------------|
| Привязка к физическим дискам | Логическая абстракция над ФС |
| Неравномерное использование дисков | Распределение объектов по разным дискам |
| Разная производительность носителей | Горячие данные → SSD, холодные → HDD |
| Масштабирование хранилища | Добавление дисков в существующее пространство |

### Создание и использование
```sql
-- Создание табличного пространства
CREATE TABLESPACE space1 LOCATION 'E:/pg_data/space1';

-- Создание объекта в конкретном пространстве
CREATE TABLE my_table (id INT) TABLESPACE space1;

-- Установка пространства по умолчанию для сессии
SET default_tablespace = space1;

-- Просмотр существующих пространств
SELECT * FROM pg_tablespace;

-- Удаление (только если пусто)
DROP TABLESPACE space1;
```

### Системные пространства
- `pg_default` — пространство по умолчанию для пользовательских объектов
- `pg_global` — для общих системных каталогов

> ⚠️ **Важно**: Табличные пространства — часть кластера. Их потеря может сделать весь кластер неработоспособным. Не размещайте их на съёмных носителях!

## 🗄️ Создание базы данных

### Базовый синтаксис
```sql
CREATE DATABASE dbname
    [WITH]
    [OWNER = owner_name]
    [TEMPLATE = template_name]
    [ENCODING = encoding]
    [LC_COLLATE = locale]
    [LC_CTYPE = locale]
    [TABLESPACE = tablespace_name]
    [CONNECTION LIMIT = conn_limit]
    [IS_TEMPLATE = true|false];
```

### Ключевые параметры

| Параметр | Описание | Значение по умолчанию |
|----------|----------|---------------------|
| `OWNER` | Владелец БД | исполнитель команды |
| `TEMPLATE` | Шаблон для копирования | `template1` |
| `ENCODING` | Кодировка символов | из шаблона |
| `LC_COLLATE` | Правила сортировки | из шаблона |
| `LC_CTYPE` | Классификация символов | из шаблона |
| `TABLESPACE` | Пространство по умолчанию | `pg_default` |
| `CONNECTION LIMIT` | Макс. число подключений | `-1` (без лимита) |
| `IS_TEMPLATE` | Можно ли использовать как шаблон | `false` |

### Шаблоны баз данных
- `template0` — «чистый» шаблон, не зависит от локали системы
- `template1` — настраиваемый шаблон, используется по умолчанию

> 💡 При создании БД с локалью, отличной от системной, используйте `TEMPLATE = template0`

### Примеры
```sql
-- Минимальное создание
CREATE DATABASE sales;

-- С параметрами
CREATE DATABASE sales
    OWNER sales_app
    ENCODING 'UTF8'
    LC_COLLATE 'ru_RU.UTF-8'
    LC_CTYPE 'ru_RU.UTF-8'
    TABLESPACE fast_storage
    CONNECTION LIMIT 20;

-- На шведской локали (через template0)
CREATE DATABASE music
    TEMPLATE template0
    ENCODING 'UTF8'
    LC_COLLATE 'sv_SE.UTF-8'
    LC_CTYPE 'sv_SE.UTF-8';
```

## ✏️ Изменение и удаление БД

### ALTER DATABASE
```sql
-- Изменить параметры
ALTER DATABASE dbname SET work_mem = '64MB';

-- Переименовать
ALTER DATABASE old_name RENAME TO new_name;

-- Сменить владельца
ALTER DATABASE dbname OWNER TO new_owner;

-- Перенести в другое табличное пространство
ALTER DATABASE dbname SET TABLESPACE new_space;

-- Сбросить параметр
ALTER DATABASE dbname RESET work_mem;
```

### DROP DATABASE
```sql
-- Удалить (с проверкой существования)
DROP DATABASE IF EXISTS dbname;
```

> ✅ Используйте `IF EXISTS` для идемпотентности скриптов развёртывания

## 🧪 Лабораторная работа №7

### Задание
Создать скрипт развёртывания БД `mydb` с:
1. Двумя табличными пространствами
2. Двумя таблицами (в разных пространствах)
3. Параметрами: кодировка, локаль, лимит подключений

### Примерная последовательность
```sql
-- 1. Создание табличных пространств
CREATE TABLESPACE myts1 LOCATION 'D:/pg_ts1';
CREATE TABLESPACE myts2 LOCATION 'D:/pg_ts2';

-- 2. Создание БД
CREATE DATABASE mydb
    OWNER postgres
    ENCODING 'UTF8'
    LC_COLLATE 'ru_RU.UTF-8'
    LC_CTYPE 'ru_RU.UTF-8'
    TABLESPACE myts1
    CONNECTION LIMIT 10
    IS_TEMPLATE false;

-- 3. Подключение к mydb и создание таблиц
\c mydb

CREATE TABLE table1 (id INT, data TEXT) TABLESPACE myts1;
CREATE TABLE table2 (id INT, info TEXT) TABLESPACE pg_default;

-- 4. Перенос таблицы в другое пространство
ALTER TABLE table1 SET TABLESPACE pg_default;
```
