## 📌 Введение в SQL

**SQL (Structured Query Language)** — язык структурированных запросов, основной стандарт для работы с реляционными СУБД.

### Ключевые особенности:
- Стандартизирован организациями **ISO** и **ANSI** (последний стандарт — **SQL:2023**)
- Декларативный язык: описываем **что** получить, а не **как**
- Кросс-технологичный: знания применимы в PostgreSQL, MySQL, Oracle, MS SQL Server
- Скриптовый: выполняется пошагово, инструкция за инструкцией

### Процедурные расширения (для полноценной алгоритмизации):
| СУБД | Расширение |
|------|-----------|
| PostgreSQL | PL/pgSQL |
| MS SQL Server | T-SQL |
| Oracle | PL/SQL |

> 💡 Чистый SQL не является Тьюринг-полным. Процедурные расширения добавляют переменные, функции, циклы, условия.

## 🗂️ Разделы языка SQL

### 1️⃣ DDL — Data Definition Language (работа с объектами)
| Инструкция | Назначение | Пример |
|-----------|-----------|--------|
| `CREATE` | Создание объекта | `CREATE TABLE items (...)` |
| `ALTER` | Изменение структуры | `ALTER TABLE items ADD COLUMN ...` |
| `DROP` | Полное удаление объекта | `DROP TABLE items` |

> ⚠️ `DROP` удаляет объект полностью (таблицу, индексы, ключи, статистику). Восстановление только из бэкапа.

### 2️⃣ DML — Data Manipulation Language (работа с данными)
| Инструкция | Назначение | Пример |
|-----------|-----------|--------|
| `SELECT` | Выборка данных | `SELECT name, price FROM items` |
| `INSERT` | Вставка данных | `INSERT INTO items VALUES (...)` |
| `UPDATE` | Обновление данных | `UPDATE items SET price = 100 WHERE id = 1` |
| `DELETE` | Удаление строк | `DELETE FROM items WHERE id = 1` |

> ⚠️ `DELETE` очищает данные, но оставляет таблицу. `TRUNCATE` — быстрая полная очистка таблицы (DDL-операция).

### 3️⃣ DCL — Data Control Language (управление правами)
| Инструкция | Назначение |
|-----------|-----------|
| `GRANT` | Выдача прав пользователю |
| `DENY` | Запрет прав |
| `REVOKE` | Отмена ранее выданных прав |

> 🔐 Обычно используется администраторами, а не разработчиками.

### 4️⃣ TCL — Transaction Control Language (транзакции)
| Инструкция | Назначение |
|-----------|-----------|
| `BEGIN` / `START TRANSACTION` | Начало транзакции |
| `COMMIT` | Подтверждение изменений |
| `ROLLBACK` | Откат изменений |
| `SAVEPOINT` | Точка сохранения внутри транзакции |

**Свойства транзакции (ACID):**
- **A**tomicity — неделимость (всё или ничего)
- **C**onsistency — согласованность данных до и после
- **I**solation — изолированность параллельных транзакций
- **D**urability — долговечность зафиксированных изменений

## 🔍 Оператор SELECT — детально

### Базовый синтаксис:
```sql
SELECT [DISTINCT] столбец1, столбец2, ...
FROM таблица
[WHERE условие]
[GROUP BY столбцы]
[HAVING условие_агрегации]
[ORDER BY столбец [ASC|DESC]]
[INTO новая_таблица];
```

### Ключевые элементы:

| Элемент | Описание | Пример |
|---------|---------|--------|
| `*` | Все столбцы | `SELECT * FROM employees` |
| `DISTINCT` | Уникальные значения | `SELECT DISTINCT country FROM customers` |
| `WHERE` | Фильтрация строк | `WHERE salary > 50000 AND department = 'IT'` |
| `GROUP BY` | Группировка для агрегации | `GROUP BY department` |
| `HAVING` | Фильтрация после группировки | `HAVING AVG(salary) > 60000` |
| `ORDER BY` | Сортировка результата | `ORDER BY name DESC` |

### Агрегатные функции:
```sql
COUNT(*)    -- количество строк
SUM(col)    -- сумма
AVG(col)    -- среднее
MIN(col)    -- минимум
MAX(col)    -- максимум
```

> 💡 **Правило**: если в SELECT есть и обычные столбцы, и агрегатные функции — обязательно используйте `GROUP BY` по всем неагрегированным столбцам.

## 🔗 Многотабличные запросы (JOIN)

### Типы соединений:

| Тип | Описание | Визуализация |
|-----|---------|-------------|
| `INNER JOIN` | Только совпадающие строки | ⭕∩⭕ |
| `LEFT JOIN` | Все строки левой таблицы + совпадения правой | ⭕→⭕ |
| `RIGHT JOIN` | Все строки правой таблицы + совпадения левой | ⭕←⭕ |
| `FULL JOIN` | Все строки обеих таблиц | ⭕∪⭕ |
| `CROSS JOIN` | Декартово произведение (каждая с каждой) | ⭕×⭕ |

### Синтаксис (современный, SQL-92):
```sql
SELECT e.name, d.department_name
FROM employees e
INNER JOIN departments d ON e.dept_id = d.id;
```

### Устаревший синтаксис (SQL-89) — не рекомендуется:
```sql
SELECT e.name, d.department_name
FROM employees e, departments d
WHERE e.dept_id = d.id;
```

> ⚠️ **Важно**: Внешние ключи (FK) обеспечивают целостность данных на уровне БД. JOIN — это способ извлечения данных. Это параллельные концепции!

## ✏️ Операции модификации данных

### INSERT — вставка данных
```sql
-- Вставка конкретных значений
INSERT INTO users (name, email) VALUES ('Иван', 'ivan@test.ru');

-- Вставка результата запроса
INSERT INTO archive_users
SELECT * FROM users WHERE created_at < '2020-01-01';
```

### UPDATE — обновление данных
```sql
UPDATE products
SET price = price * 1.1
WHERE category = 'electronics';
```

### DELETE vs TRUNCATE
| Характеристика | DELETE | TRUNCATE |
|---------------|--------|----------|
| Тип операции | DML | DDL |
| Скорость | Медленнее (логируется построчно) | Быстрее |
| Условие WHERE | Поддерживается | Не поддерживается |
| Восстановление | Возможно через ROLLBACK | Не восстанавливается |
| Сброс автоинкремента | Нет | Да (в большинстве СУБД) |

> 💡 **Для PostgreSQL**: `TRUNCATE` предпочтительнее для полной очистки больших таблиц из-за механизма MVCC.

## 👁️ Представления (Views)

### Что такое представление?
**View** — именованный сохранённый SELECT-запрос, который выполняется динамически при обращении.

```sql
CREATE VIEW v_employee_info AS
SELECT e.name, d.dept_name, e.salary
FROM employees e
JOIN departments d ON e.dept_id = d.id;

-- Использование
SELECT * FROM v_employee_info WHERE salary > 50000;
```

### Зачем нужны представления?

| Причина | Описание |
|---------|---------|
| 🔹 Упрощение | Скрывают сложную логику запросов, предоставляют удобный интерфейс |
| 🔹 Безопасность | Ограничивают доступ к чувствительным данным (показывают только нужные столбцы/строки) |
| 🔹 Абстракция (API) | Позволяют изменять внутреннюю структуру БД без влияния на потребителей данных |

> 💡 **Best Practice**: Именуйте представления с префиксом `v_` или `view_` для отличия от таблиц.

## 🛠️ Практические советы

### Работа в pgAdmin:
1. **Не пишите код напрямую в окне запросов** — используйте внешний редактор с автосохранением
2. **Выделяйте часть кода** перед выполнением, чтобы запустить только нужное
3. **Обновляйте дерево объектов** (ПКМ → Refresh) после создания/удаления объектов
4. **Используйте комментарии**:
   ```sql
   -- Однострочный комментарий
   /* Многострочный
      комментарий */
   ```

### Читаемость кода:
```sql
-- ✅ Хорошо: переносы и отступы
SELECT 
    employee_id,
    first_name,
    salary
FROM employees
WHERE department = 'IT'
ORDER BY salary DESC;

-- ⚠️ Допустимо: запятая в начале строки
SELECT 
    employee_id
  , first_name
  , salary
FROM employees;
```

### Оптимизация порядка операций в SELECT:
```
FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY
```
> Система сначала фильтрует данные, потом группирует, потом сортирует — это эффективнее, чем сортировать всё подряд.
