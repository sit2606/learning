## 🔹 Введение в PL/PGSQL

### SQL vs PL/PGSQL
| Характеристика | SQL (чистый) | PL/PGSQL |
|---------------|-------------|----------|
| Тип языка | Декларативный | Процедурный |
| Тьюринг-полнота | ❌ Нет | ✅ Да |
| Назначение | Создание, чтение, обновление, удаление данных | Написание функций, процедур, триггеров |
| Управляющие конструкции | Ограничены | IF, CASE, циклы (LOOP, WHILE, FOR) |

### Историческая справка
- **1970-е**: разработка SQL компанией IBM
- **1986**: стандартизация ANSI
- **1987**: стандартизация ISO
- **PL/PGSQL**: появился в PostgreSQL 6.4 (1998 г.)

> **ANSI SQL** — сленговое обозначение кода, совместимого с разными СУБД (кросс-платформенного)

## 🔹 Категории операторов SQL

### 1. DDL (Data Definition Language) — определение данных
```sql
CREATE TABLE importer (...);     -- создание объекта
ALTER TABLE importer ADD ...;    -- изменение структуры
DROP TABLE importer;             -- удаление объекта
```

### 2. DML (Data Manipulation Language) — манипулирование данными
```sql
SELECT company_id, name FROM importer WHERE ...;  -- выборка
INSERT INTO importer VALUES (...);                -- вставка
UPDATE importer SET name = '...' WHERE ...;       -- обновление
DELETE FROM importer WHERE ...;                   -- удаление
```

### 3. DCL (Data Control Language) — управление правами
```sql
GRANT SELECT ON importer TO public;   -- выдать право
DENY SELECT ON importer TO public;    -- запретить
REVOKE SELECT ON importer FROM public; -- отозвать право
```

### 4. Транзакции
```sql
BEGIN;          -- начало транзакции (также BEGIN TRANSACTION, BEGIN WORK)
-- операторы...
COMMIT;         -- подтверждение изменений
ROLLBACK;       -- откат изменений
```

## 🔹 Идентификаторы и именование объектов

### Жёсткие правила
- Начинаются с **латинской буквы** или **подчёркивания** `_`
- Далее: буквы, цифры, подчёркивания
- **Цифра в начале запрещена**

### Рекомендации по именованию
| Объект | Префикс | Пример |
|--------|---------|--------|
| Таблица | `t_` | `t_importer` |
| Представление | `v_` | `v_active_users` |
| Индекс | `ix_` | `ix_user_email` |
| Процедура | `sp_` | `sp_calculate_salary` |
| Функция | `fn_` | `fn_get_user` |
| Триггер | `tg_` | `tg_before_insert` |

### ⚠️ Важная особенность PostgreSQL
> Все имена объектов **автоматически приводятся к нижнему регистру** при хранении в системных словарях.

```sql
-- Создание таблицы в CamelCase
CREATE TABLE "ZP_of_Employees" (...);  -- с двойными кавычками

-- Обращение:
SELECT * FROM ZP_of_Employees;         -- ✅ работает (приводится к нижнему регистру)
SELECT * FROM "ZP_of_Employees";       -- ✅ работает (точное совпадение)
SELECT * FROM "zp_of_employees";       -- ❌ ошибка (не найдено)
```

**💡 Лайфхак**: используйте только **нижний регистр + подчёркивания** — и проблем с регистром не будет!

## 🔹 Типы данных в PostgreSQL

### Основные категории (используются в 90% случаев)
1. **Числовые**: `INTEGER`, `BIGINT`, `NUMERIC(p,s)`, `REAL`, `DOUBLE PRECISION`
2. **Строковые**: 
   - `CHAR(n)` — фиксированная длина (всегда выделяет n байт)
   - `VARCHAR(n)` — переменная длина (выделяет по факту, лимит n)
   - `TEXT` — неограниченная строка
3. **Дата/время**: `DATE`, `TIME`, `TIMESTAMP`, `TIMESTAMPTZ`

### Специализированные типы (редко используются)
- `MONEY` — денежные значения с учётом локали
- `BOOLEAN` — логический тип (`TRUE`/`FALSE`, `1`/`0`, `'yes'`/`'no'`)
- `JSON`/`JSONB` — работа с JSON-документами
- `ARRAY` — массивы значений
- `GEOMETRY` — точки, прямоугольники, полигоны
- `UUID`, `INET`, `XML`, диапазоны, композитные типы, псевдотипы

> **Важно**: в PostgreSQL `VARCHAR` работает **быстрее** `CHAR` — уникальная особенность!

## 🔹 Переменные и анонимные блоки кода

### Структура анонимного блока
```plpgsql
DO $$
DECLARE
    -- Зона объявления переменных
    counter INTEGER := 1;
    name VARCHAR(50) := 'John';
BEGIN
    -- Зона выполнения кода
    IF counter = 1 THEN
        RAISE NOTICE 'Hello, %', name;
    END IF;
    
    -- Обработка исключений (опционально)
EXCEPTION
    WHEN division_by_zero THEN
        RAISE NOTICE 'Ошибка: деление на ноль';
END $$;
```

### Особенности переменных
- Объявляются **только** в блоке `DECLARE`
- **Локальные** — видны только в пределах блока
- Глобальных пользовательских переменных **нет** (используйте таблицы для хранения)
- Инициализация: `:=` или `DEFAULT`

### Присваивание результата запроса
```plpgsql
DECLARE
    emp_name VARCHAR(100);
BEGIN
    -- Вариант 1 (сокращённый)
    emp_name := (SELECT firstname FROM employees WHERE lastname = 'Smith');
    
    -- Вариант 2 (более читаемый)
    SELECT firstname INTO emp_name 
    FROM employees 
    WHERE lastname = 'Smith';
END;
```

> ⚠️ Подзапрос должен возвращать **ровно одну строку и один столбец**, иначе — ошибка!

## 🔹 Управляющие конструкции

### Условные операторы
```plpgsql
IF condition THEN
    -- действия
ELSIF other_condition THEN
    -- другие действия
ELSE
    -- действия по умолчанию
END IF;
```

### Циклы
```plpgsql
-- LOOP (бесконечный, требует EXIT)
LOOP
    EXIT WHEN condition;
    -- действия
END LOOP;

-- WHILE
WHILE condition LOOP
    -- действия
END LOOP;

-- FOR (перебор диапазона)
FOR i IN 1..10 LOOP
    RAISE NOTICE 'Iteration: %', i;
END LOOP;
```

### Логические операторы и приоритет
```
Приоритет (по убыванию):
1. NOT
2. AND  
3. OR
```
```plpgsql
-- Всегда используйте скобки для ясности:
IF (dept = 'sales' AND (shift = 'evening' OR shift = 'night')) THEN
    -- ...
END IF;
```

## 🔹 Выражения и функции

### Арифметические и строковые операции
```sql
-- Математика: + - * / % (остаток)
SELECT price * 2 - 100 AS discounted_price FROM products;

-- Конкатенация строк: || (две вертикальные черты)
SELECT lastname || ', ' || firstname AS full_name FROM employees;

-- Приведение типов:
SELECT CAST(value AS INTEGER);      -- ANSI-стиль (кросс-платформенный)
SELECT value::INTEGER;              -- PostgreSQL-стиль (короче)
```

### Встроенные функции
| Категория | Примеры |
|-----------|---------|
| Математические | `ROUND()`, `CEIL()`, `FLOOR()`, `SIN()`, `PI()` |
| Строковые | `LOWER()`, `UPPER()`, `SUBSTRING()`, `LENGTH()`, `TRIM()` |
| Дата/время | `CURRENT_DATE`, `CURRENT_TIMESTAMP`, `AGE()`, `EXTRACT()` |
| Агрегатные | `COUNT()`, `SUM()`, `AVG()`, `MIN()`, `MAX()` |
| Системные | `CURRENT_DATABASE()`, `CURRENT_USER`, `SESSION_USER` |

## 🔹 Выполнение кода в PostgreSQL

### 4 способа запуска
1. **Одиночные запросы** — для тестирования в pgAdmin
2. **Анонимные блоки (DO)** — для разовых процедурных скриптов
3. **Хранимые функции/процедуры** — для промышленного использования
4. **SQL-файлы** — для развёртывания и DevOps

### Почему хранимые процедуры эффективнее?
```
Обычный запрос:
[Парсинг] → [Проверка] → [Оптимизация] → [Планирование] → [Компиляция] → [Выполнение]

Хранимая процедура:
[Вызов] → [Выполнение]  (уже скомпилирована и хранится на сервере)
```

**Преимущества**:
- ✅ Меньше трафика (передаётся только вызов)
- ✅ Быстрее выполнение (нет повторной компиляции)
- ✅ Централизованное управление логикой

**Недостатки**:
- ⚠️ Требует перекомпиляции при изменении структуры БД
- ⚠️ Сложнее отладка

### Просмотр плана выполнения
```sql
EXPLAIN SELECT * FROM tickets WHERE flight_id = 123;
EXPLAIN ANALYZE SELECT ...;  -- с фактическим выполнением
```

## 🔹 Практические советы

### Работа в pgAdmin
- **Ctrl+Enter** — выполнить запрос
- **Ctrl+Пробел** — автодополнение
- **Script → Create** — сгенерировать DDL-скрипт объекта
- Всегда проверяйте **подключённую БД** перед выполнением

### Отладка и безопасность
```plpgsql
-- Вывод отладочных сообщений
RAISE NOTICE 'Debug: value = %', variable;
RAISE WARNING 'Warning message';
RAISE EXCEPTION 'Critical error';  -- прервёт выполнение

-- Обработка ошибок
BEGIN
    -- рискованный код
EXCEPTION
    WHEN division_by_zero THEN
        RAISE NOTICE 'Попытка деления на ноль';
    WHEN OTHERS THEN
        RAISE NOTICE 'Неизвестная ошибка: %', SQLERRM;
END;
```

### Копирование таблиц
```sql
-- Создать таблицу с данными
CREATE TABLE new_table AS 
SELECT * FROM original_table;

-- Создать пустую таблицу со структурой
CREATE TABLE new_table AS 
SELECT * FROM original_table 
WHERE 1=0;  -- или LIMIT 0

-- Переименовать таблицу
ALTER TABLE old_name RENAME TO new_name;
```
