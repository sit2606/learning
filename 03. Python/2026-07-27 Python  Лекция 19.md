## 1. Введение: Open Source и наработка опыта
Для наработки реального опыта рекомендуется участвовать в **Open Source** проектах. Это дает возможность поработать в распределенной команде и получить строчки кода, которые можно показать работодателю.
*   На GitHub для отслеживания задач используется раздел **Issues** (список багов и запросов на новые функции — **Feature Request**).
*   Мейнтейнеры проектов часто помечают простые задачи специальным тегом **Good First Issue**. Он предназначен для новичков в конкретном проекте и не требует глубокого знания всей архитектуры.
*   Процесс внесения кода включает создание **Pull Request (PR)** и прохождение **Code Review** (проверки кода другими разработчиками).
*   *Примечание:* Упоминание LinkedIn как инструмента для поиска работы (в РФ запрещен, поэтому нужно учитывать специфику локального или глобального рынка). GitHub на момент лекции работает.

## 2. Введение в PyQt и проблемы совместимости
Переход от встроенного `tkinter` к более мощному фреймворку **PyQt** (обертка над библиотекой **Qt** для Python).
*   **История Qt:** Изначально создавалась компанией Trolltech, затем была куплена Nokia, позже продана и выделена в независимую компанию **Qt Group** (крупный игрок на рынке, акции торгуются на бирже).
*   **PyQt vs PySide:** Существуют две основные обертки. Для учебных целей они практически идентичны (различаются в основном имена модулей).
*   **Проблема совместимости версий:** Инструмент **Qt Designer** (графический редактор интерфейсов), входящий в состав PyQt6, не работает с последними версиями Python (3.11, 3.12, 3.13, 3.14). Он стабильно работает только на Python 3.10 и ниже.
*   *Решение:* Либо использовать **PyQt5** с новейшим Python (3.14), либо использовать **PyQt6**, но откатиться на Python 3.10.
*   В отличие от `tkinter`, PyQt требует обязательной установки через `pip` и наличия файла **requirements.txt** в репозитории.

## 3. Паттерн MVC и разбор 7-го задания (Фермерские рынки)
При переходе от консольного приложения к графическому (GUI) критически важно использовать паттерн **MVC (Model-View-Controller)**.
*   **Принцип открытости-закрытости (Принцип Майера):** Приложение должно быть открыто для расширения (добавления новых "кирпичиков"), но закрыто для модификации (не нужно переписывать старый код).
*   **Разбор логики 7-го задания:** Если пользователь вводит почтовый индекс, которого нет в базе фермерских рынков, приложение **не должно** просто выдавать ошибку "рынки не найдены". Пользователь хочет найти ближайшие рынки. Необходимо интегрировать дополнительную базу геолокаций, брать координаты введенного индекса и искать рынки в заданном радиусе (например, 100 миль), игнорируя границы почтовых индексов.
*   **Middle Tier (Промежуточный уровень):** Вспомогательные функции (например, файл `util.py` для расчета расстояний между координатами или форматирования сторон света S, N, W, E). Они не относятся ни к Модели (хранению данных), ни к View (отображению), так как универсальны и не должны дублироваться в разных версиях модели.
*   **Главное правило:** При создании GUI-версии **Модель должна остаться абсолютно неизменной** (ни на один байт). Меняются только View (отрисовка кнопок вместо `print`) и Controller (обработчики нажатий вместо консольного `input`).

## 4. Настройка окружения и установка PyQt5
*   Создание виртуального окружения (`venv`) с привязкой к конкретной версии исполняемого файла Python (например, 3.14 или 3.10).
*   Установка пакетов: `pip install pyqt5 pyqt5-tools` (или `pyqt5-designer`). Пакетный менеджер `pip` автоматически подтянет **зависимости** (sip, qt5 и т.д.).

## 5. Работа в Qt Designer и структура UI-файлов
**Qt Designer** — визуальный редактор для проектирования интерфейсов.
*   **Типы форм:** Dialog (диалоговое окно, часто модальное), Main Window (главное окно с меню и статус-баром), Custom Widget.
*   **Виджеты:** `QLabel` (метка), `QLineEdit` (однострочное текстовое поле), `QDial` (крутилка/регулятор), `QPushButton` (кнопка).
*   **Именование объектов:** Рекомендуется использовать смысловые префиксы (`lblUsername`, `txtUsername`, `btnSubmit`, `dlVolume`).
*   💡 **Новое понятие / Правило:** Все классы библиотеки Qt начинаются с заглавной буквы **Q**. *Никогда не называйте свои собственные классы на букву Q*, чтобы избежать путаницы в коде.
*   Сохранение проекта дает файл формата **XML** с расширением `.ui`. Этот файл содержит только метаданные (размеры, шрифты, иерархию), но не содержит исполняемого кода и логики.

## 6. Компиляция UI в Python-код
Для превращения `.ui` (XML) в Python-код используется компилятор **pyuic** (например, `pyuic5`).
*   *Способ 1 (перенаправление):* `pyuic5 main.ui > main.py`
*   *Способ 2 (флаг -o):* `pyuic5 main.ui -o main.py`
*   ⚠️ **Важное правило:** Сгенерированный `.py` файл **категорически запрещено редактировать вручную**. При любом изменении дизайна и повторной компиляции ваши ручные правки будут уничтожены.
*   **Запуск приложения:** Создается отдельный файл (например, `app.py`), который импортирует сгенерированный класс, создает объект **QApplication** (всё приложение), инициализирует **QMainWindow**, вызывает метод `setupUI()` и запускает главный цикл обработки событий через `sys.exit(app.exec_())`.

## 7. Менеджеры размещения (Layouts)
Отказ от жестких абсолютных координат (x, y) в пользу адаптивных менеджеров размещения:
*   **Grid Layout** (табличное размещение).
*   **VBox Layout** (вертикальное размещение).
*   **HBox Layout** (горизонтальное размещение).
*   *Лайфхак:* Визуальный редактор Qt Designer иногда капризничает при сложной вложенности Layouts. В таких случаях `.ui` файл (XML) можно открыть в текстовом редакторе и поправить теги вложенности вручную.

## 8. Сигналы и слоты
💡 **Новые понятия:** В терминологии Qt события называются **Сигналы (Signals)**, а их обработчики — **Слоты (Slots)**.
*   **Внутри Designer:** Можно напрямую связать сигнал одного виджета со слотом другого без написания кода (например, сигнал `valueChanged` от крутилки `QDial` на слот `setNum` метки `QLabel`).
*   **В коде Python:** Для подключения кастомных функций используется метод `.connect()`. Связывание сигналов с пользовательскими слотами прописывается в `app.py` строго **после** вызова `setupUI()` (иначе объекты еще не существуют) и **до** вызова `show()`.

## 9. Разбор примеров кода (ModUI)
Серия небольших примеров демонстрирует различные возможности PyQt:
*   **Альтернативный подход:** Наследование своего класса напрямую от `QMainWindow` (вместо использования сгенерированного класса-обертки).
*   **Кнопки:** Свойство `checkable` (кнопка-флажок, фиксирует состояние нажатия), проверка состояния через `isChecked()`.
*   **Множественные слоты:** На один сигнал (клик) можно повесить несколько разных обработчиков.
*   **Управление состоянием:** Программное изменение текста и отключение кнопки через `setEnabled(False)` (кнопка становится серой и не реагирует на клики).
*   **Цепочки событий:** Клик по кнопке меняет заголовок окна -> Срабатывает событие смены заголовка -> Обработчик этого события отключает кнопку.
*   **События мыши:** Переопределение методов `mousePressEvent`, `mouseReleaseEvent`, `mouseMoveEvent`, `mouseDoubleClickEvent`. Анализ аргументов события позволяет понять, какая именно кнопка мыши (левая, правая, средняя) была нажата.
*   **Контекстное меню:** Использование классов **QMenu** и **QAction** *(в лекции пример не сработал из-за изменений в новой версии библиотеки, преподаватель обещал исправить и перезалить код)*.
*   **Горячие клавиши в меню:** Использование символа `&` (амперсанд) перед буквой в названии пункта меню (например, `&Open`) создает **Accelerator** (быстрый вызов через `Alt + O`).

## 10. Крупный пример: GUI для Zip-кодов (PyCharm и динамическая загрузка)
Демонстрация полноценного приложения с использованием PyCharm и PyQt6 (на Python 3.10).
*   **External Tools в PyCharm:** Настройка быстрых команд в контекстном меню для запуска `designer.exe` и `pyuic6` с автоматической подстановкой имен файлов.
*   💡 **Новое понятие:** **loadUi()** — функция, позволяющая загрузить `.ui` файл и сгенерировать Python-объект **динамически (на лету)** прямо в коде, без предварительной компиляции через `pyuic`. Это удобно для диалоговых окон (например, окна Логина).
*   Архитектурно приложение использует ту же самую **Модель** и **Middle Tier** (`util.py`), что и консольная версия.

## 11. Краткий обзор wxPython
Третья популярная библиотека для создания GUI (после Tkinter и PyQt).
*   **Особенность:** Интерфейс выглядит максимально нативно (как стандартные окна Windows).
*   💡 **Новое понятие:** Вместо Layouts в wxPython используются **Sizers** (BoxSizer, GridSizer, FlexGridSizer, GridBagSizer, StaticBoxSizer).
*   **Инструмент дизайна:** **wxFormBuilder** (скачивается отдельно с SourceForge). В отличие от Qt Designer, он генерирует готовый `.py` файл напрямую, без необходимости использовать отдельный компилятор.
*   wxPython не имеет проблем с совместимостью с новейшими версиями Python.
