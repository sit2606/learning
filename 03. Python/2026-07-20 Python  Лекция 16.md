## 1. Введение. Многопоточное приложение — что это и зачем

Лекция начинается с вопроса: как мы писали код до сих пор и как наши приложения выполнялись. Рассматривается пример из прошлого занятия — программа с доступом к базе данных.

Типичный запуск: `python имя_файла.py`. Что при этом происходит в системе?

---

## 2. Как запускается Python-скрипт. Файл, интерпретатор, процесс

- Операционная система находит файл **python.exe** (Windows) или исполняемый файл **python3** (Linux/macOS).
- Внутри исполняемого файла «зашит» **интерпретатор**, который выполняет код из `.py`-файла.
- Интерпретатор может быть взят:
  - из **виртуального окружения** (папка `venv`, внутри которой есть копия интерпретатора `python.exe`);
  - из глобальной папки установки Python, если виртуальное окружение не используется. Путь ищется через системную переменную окружения **PATH**, которая содержит пути ко всем исполняемым файлам.
- Операционная система читает файл `python.exe` с диска, загружает его содержимое в память и передаёт управление загруженному коду.

> **Процесс** — понятие, соответствующее исполняемой в данный момент программе.

Важно различать:
- **файл на диске** (исполняемый образ, бинарный файл) — это просто данные, «мёртвая» вещь;
- **процесс** — выполняющийся код, загруженный в память и «живой».

Чтобы «оживить» файл, нужно попросить ОС прочитать его содержимое, загрузить машинные инструкции в память и начать их выполнение.

## 3. Понятие процесса. PID

> **PID (Process ID)** — уникальный идентификатор процесса в операционной системе.

Ключевые факты о PID:
- PID находится в диапазоне **от 0 до 65535**.
- Это **16-битное число** (2 байта, 16 бит).
- В любой момент в системе не может быть больше **65536 процессов**.
- PID **0** — специальный системный **псевдопроцесс «бездействие системы»** (System Idle).
- PID уникален только **в текущий момент времени**.
- PID **повторно используются**: после завершения процесса его PID может быть назначен новому процессу.
- Один и тот же PID в разные моменты времени может соответствовать разным программам.
- **Гарантии**:
  - среди выполняемых сейчас процессов не может быть двух с одинаковым PID;
  - выполняющийся процесс не может сменить свой PID.

> Одна и та же программа может быть запущена несколько раз, и каждый запуск создаёт **отдельный процесс** со своим PID. Программа и процесс — не идентичны.

---

## 4. Наблюдение за процессами. Task Manager, Process Explorer, ps, htop

Для наблюдения за процессами:
- **Task Manager** — стандартный диспетчер задач Windows.
- **Process Explorer** — продвинутая утилита от компании **Sysinternals**. Основатель — **Марк Русинович** (Mark Russinovich), известный специалист по Windows, долгое время работавший в Microsoft. Sysinternals производит утилиты для администрирования и углублённого программирования.
- В **Linux/macOS**: команда **`ps`** (список процессов) и **`htop`** (графическое отображение загрузки).

Каждая строка в списке процессов — отдельный процесс со своим PID.

> PID пригодится при работе с **сокетами** и сетевым взаимодействием: для понимания, какой процесс участвует в обмене данными по сети.

---

## 5. Свойства и особенности PID

- Если приложение читает свой PID, то от запуска к запуску он будет отличаться.
- Если приложение наблюдает за другими процессами и ведёт журнал их PID, нужно учитывать, что PID может быть переиспользован.
- Не следует считать PID уникальным в пределах всего сеанса работы ОС.

## 6. Параллелизм и разделение времени. Кванты времени

Все процессы присутствуют в системе одновременно, но **не выполняются одновременно** в строгом смысле.

Для истинного параллелизма нужно количество процессоров, равное количеству процессов. В обычных компьютерах это невозможно (сотни процессов, но единицы ядер).

Пример из лекции: на ноутбуке 8 физических ядер Intel с **Hyper-Threading** (гипертрейдинг), что даёт 16 логических процессоров. Гипертрейдинговые ядра не полностью независимы — у них общие ресурсы, поэтому прирост не двукратный.

> **Разделение времени (time sharing)** — подход, при котором один ресурс используется разными клиентами по очереди. Аналогия: timeshare на виллу, когда каждый владелец пользуется ей в свой месяц.

- Процессы конкурируют за процессоры.
- Каждый процесс получает **квант времени** (например, 1 мс).
- Операционная система переключает процессор между процессами.
- Создаётся **иллюзия одновременности** выполнения.
- Код каждого процесса продвигается вперёд понемногу.

> **Переключение контекста** — сохранение состояния текущего процесса и загрузка состояния следующего для продолжения выполнения.

## 7. Голодание (starvation)

> **Голодание (starvation)** — ситуация, когда процесс очень долго не получает квант времени и не продвигается в выполнении кода.

Причины:
- ошибки в реализации ОС;
- неправильная настройка приоритетов процессов.

В нормально работающей системе голодания не происходит — все процессы понемногу продвигаются.

## 8. Историческое развитие: от однозадачности к многоядерности

### Однозадачные системы (≈40 лет назад)
- Одно ядро, один процесс.
- **Однопользовательские** и **однозадачные** системы.
- Пример: запуск игры Doom — никакой другой код не выполнялся.
- Для запуска другой программы нужно завершить текущую.

### Многозадачные системы
- Процессор по-прежнему одноядерный, но появилась **иллюзия многозадачности** за счёт разделения времени.
- Пример: первые версии Windows.

### Кооперативная многозадачность
- В ранних Windows (3.0, 3.1, 3.11, 95) использовался **кооперативный режим многозадачности** (процессы «договариваются» вести себя хорошо).
- Процесс мог получить доступ к памяти другого процесса и изменить её.
- Устойчивость обеспечивалась только соглашениями.
- Ошибка в одном процессе могла привести к краху всей ОС.

### Вытесняющая многозадачность и изоляция
- Пришло понимание, что **изоляция процессов** — необходимое условие устойчивости.
- Если процесс не может вмешаться в деятельность другого, он не может ничего испортить.

### Многопроцессорные системы
- Возможность установки нескольких процессоров на материнскую плату.
- Ограничение: физический размер платы (обычно 2 слота, максимум 4).

### Многоядерные процессоры
- Развитие пошло по пути размещения нескольких процессоров внутри одного чипа.
- Основной путь повышения производительности последние 20+ лет — **наращивание количества ядер**.

### Частота процессора
- Ранее производительность повышали увеличением частоты.
- Упёрлись в физические ограничения (микроволновые эффекты на частотах, приближающихся к десяткам ГГц).
- Сейчас частоты остаются в области единиц ГГц (3–5 ГГц).

### Ограничения по ядрам
- 16, 32, 48, 64 ядра — уже не экзотика, но делать больше тяжело и дорого.
- В архитектуре центрального процессора даже сотня ядер — сложная задача.
- В GPU другая архитектура — там ядер могут быть тысячи.

### Квантовые компьютеры
- Существуют, но это исследовательская технология.
- Лектор участвует в двух проектах по квантовым вычислениям.
- Пока неясно, как будут выглядеть приложения для них.

## 9. Пути повышения производительности

Если код выполняется медленно, можно:
1. **Выбрать другой алгоритм** — переписать код, чтобы сам алгоритм был быстрее. Продуктивный подход, но часто тяжёлый, долгий и дорогой.
2. **Запустить несколько процессов параллельно** — разбить задачу на части и выполнять каждую на отдельном ядре.

> **HPC (High Performance Computing)** — высокопроизводительные вычисления, где параллелизм достигается разбиением задачи на части, каждая из которых выполняется на отдельном ядре.

Пример: моделирование распределения температуры в металлической заготовке — два процесса делят работу пополам.

Проблема: процессы изолированы и общаться между собой им тяжело.

## 10. Изоляция процессов. Виртуальная память

Процессы сильно изолированы друг от друга:
- Процесс не может подсмотреть код другого процесса.
- Процесс не может прочитать или изменить данные другого процесса.
- Это обеспечивает **устойчивость системы**: если один процесс содержит ошибку, ОС снимает только его, остальные продолжают работать.

> **Виртуальная память** — механизм, при котором каждый процесс имеет иллюзию, что ему доступна вся память (и даже больше, чем физически есть). Процесс не видит память других процессов и ядра ОС.

Следствие: у двух процессов Python не может быть общих переменных, потому что не может быть общей памяти.

---

## 11. Межпроцессное взаимодействие (IPC)

> **IPC (Inter-Process Communication)** — средства межпроцессного взаимодействия.

Примеры IPC:
- обмен сообщениями;
- чтение и запись общих файлов;
- **конвейеры (pipes, пайпы)**;
- **разделяемая память** (специально выделенная область);
- **семафоры**.

Эти средства нужно специально включать и настраивать, они не очень быстрые.

## 12. Потоки (threads). TID

Решение проблемы изоляции процессов — создание «мини-процессов» внутри одного процесса.

> **Поток (thread)** — легковесный процесс, фрагмент кода, выполняющийся внутри процесса. Также иногда переводят как «нить», но лектор предпочитает термин «поток».

> **Режим многопоточности** — выполнение нескольких потоков в рамках одного процесса, в противовес многопроцессному выполнению.

> **TID (Thread ID)** — уникальный идентификатор потока, аналог PID для потоков.

Свойства TID:
- Число от 0 до 65535.
- Уникален только в текущий момент.
- Может повторно использоваться для новых потоков.

Потоки можно видеть в свойствах процесса (вкладка Threads в Process Explorer).

---

## 13. Структура потока. Что у потока есть

> **Поток** — наименьшая единица выполнения с набором инструкций (кодом), не зависящая от других единиц.

- Поток является частью процесса, работает в рамках процесса.
- Поток **не имеет собственной глобальной памяти**.
- У потока есть **свой стек** (поток может вызывать функции).
- **Глобальная память и память объектов** — общие для всех потоков процесса.
- Поток имеет: **начальную точку**, **последовательность выполнения** и **результат**.
- При прерывании (конец кванта времени) поток сохраняет:
  - **указатель на текущую инструкцию** (программный счётчик);
  - **набор регистров процессора**;
  - **стек**;
  - **уникальный идентификатор (TID)**.

---

## 14. Преимущества многопоточности

1. **Производительность**: разбиение вычисления на потоки, выполняемые параллельно, повышает скорость.
2. **Отзывчивость программы**: программа не подвисает. Пример: среда разработки **Spyder** — при ожидании пользовательского ввода (`input`) можно продолжать работать с меню и диалогами. Без многопоточности это было бы невозможно.
3. **Общий доступ к памяти**: потоки легко обмениваются данными через глобальные переменные.
4. **Эффективное использование процессора**: загрузка ядер без простоя.

## 15. Модули `_thread` и `threading` в Python

Два модуля для реализации потоков:

| Модуль | Подход |
|---|---|
| **`_thread`** | Не объектно-ориентированный. Код потока задаётся **функцией**. |
| **`threading`** | Объектно-ориентированный. Каждый поток — **объект** (класс). |

> Ранее существовал модуль `thread` (без подчёркивания) — он **устаревший**, переименован в `_thread`. Не использовать `thread` без подчёркивания.

## 16. Пример `thread_example` (модуль `_thread`)

Файл: `thread_example.py` (папка `mod_thread`).

- Функция **`print_time(thread_name, delay)`**:
  - печатает сообщение с именем потока и задержкой;
  - входит в цикл, засыпает на `delay` секунд (**`sleep`** из модуля `time`);
  - печатает имя потока и текущее время;
  - 5 итераций.
- Запуск: **`_thread.start_new_thread(print_time, ("Thread-1", 2))`** — передаётся имя функции и кортеж позиционных параметров.
- Функцию `print_time` вручную не вызываем — её запускает `start_new_thread` в отдельном потоке.
- **`sleep`** тормозит только текущий поток, не влияя на другие.
- Обработка исключений: если не удалось запустить поток — вывод ошибки.
- **Главный поток** продолжает бесконечный цикл, печатая возрастающие значения с интервалом 3 секунды.

Итого потоков: **3** (главный + 2 дочерних). Дочерние завершаются после 5 итераций, главный продолжает работать.

Наблюдения:
- Поток с меньшей задержкой завершается первым.
- Временные метки сообщений потока с задержкой 4 секунды отличаются на 4 секунды.

## 17. Пример `HelloThreadsExample` (модуль `threading`)

Файл: `HelloThreadsExample.py`.

- Класс наследуется от **`threading.Thread`**.
- Код потока помещается в метод **`run`**.
- В `run`: пауза 2 секунды, чтение и печать текущей даты/времени.
- Основной код (главный поток):
  - печатает количество потоков и их список — изначально только **MainThread**;
  - в цикле создаёт 10 экземпляров класса и запускает через **`start()`**;
  - печатает количество активных потоков после запуска.

> В любом процессе есть как минимум один поток — **главный поток (MainThread)**.

Важно: при запуске из IDE (Spyder) видны дополнительные потоки самой IDE (например, 7 вместо 1), что создаёт путаницу. При запуске из чистого терминала — ровно 1 главный + 10 дочерних = 11.

Порядок вывода сообщений потоков **не совпадает** с порядком их создания: потоки создаются как объекты последовательно (Thread-1, Thread-2, …), но операционная система сама решает, какому потоку дать квант времени.

## 18. Методы потока: run, start, join, getName, setName, isAlive

| Метод | Назначение |
|---|---|
| **`run()`** | Содержит код, выполняемый в потоке. Точка входа. **Не вызывать вручную** для запуска потока. |
| **`start()`** | Запускает поток на выполнение. Вызывает `run()` в отдельном потоке. |
| **`join()`** | Ожидает завершения указанного потока. Блокирует код главного потока, пока дочерний не завершится. Может принимать необязательный параметр времени. |
| **`getName()`** | Узнать имя потока. |
| **`setName()`** | Установить имя потока. |
| **`isAlive()`** | Проверить, выполняется ли ещё поток. |

Альтернативный способ создания потока: объект `Thread` с параметром **`target`** (функция, которую поток должен выполнять) — элементы функционального программирования.

### Пример `threads1fun`
- Два потока, каждый выполняет функцию **`prescript`** с разными аргументами:
  - `("f1.txt", 200)` и `("f2.txt", 1000)`.
- `prescript` открывает файл на запись; если второй аргумент > 500 — записывает большой демотекст, иначе — маленький.
- Создание объектов (строки 18–19), запуск через `start()` (строки 24–25), ожидание через `join()`.
- Результат: два файла с разным содержимым. Многопоточность эффективна, потому что операции ввода-вывода медленные и могут перекрываться.

## 19. Недетерминированность потоков. Средства синхронизации

- Без явных **средств синхронизации** потоки запускаются **недетерминированно**.
- Создание объекта потока первым не гарантирует, что он запустится первым.
- ОС сама выбирает, какому потоку дать квант времени.
- Рассчитывать на определённый порядок выполнения без синхронизации **нельзя**.

Примеры средств синхронизации:
- **`join()`** — ожидание завершения потока;
- механизмы «подожди, пока я выполню вычисление, потом работай».

## 20. Ошибка: вызов run вместо start

Если по ошибке вызвать **`run()`** вместо **`start()`**:
- код будет работать, но **последовательно в главном потоке**, без создания дополнительных потоков;
- задержки **суммируются**, а не перекрываются;
- `join()` не имеет смысла, так как потоков нет.

Демонстрация: при `run()` общее время ≈ 70 секунд (задержки суммируются), при `start()` ≈ 50 секунд (задержки в потоках перекрываются, берётся максимум).

> **Вывод**: всегда использовать `start()`, никогда не вызывать `run()` напрямую для запуска потока.

## 21. GIL — Global Interpreter Lock

> **GIL (Global Interpreter Lock)** — механизм в стандартном интерпретаторе Python (CPython), позволяющий выполнять код только **в одном потоке в любой момент времени**.

- Это осознанное решение **Гвидо ван Россума** (Guido van Rossum), главного создателя Python.
- Потоки можно организовать, но интерпретатор выполняет код потоков **последовательно**, без перекрытия по времени.
- На временной диаграмме: выполняется код первого потока, затем второго, третьего — но никогда не одновременно.

Варианты интерпретаторов:
- **CPython** (стандартный) — поддерживает GIL.
- **CPython free-threaded** — экспериментальный вариант без GIL, поддерживает многопоточное выполнение.
- **PyPy** и некоторые другие — не поддерживают GIL.

> **Вывод**: для вычислительных задач (CPU-bound) многопоточность в стандартном CPython **бессмысленна**. Для операций ввода-вывода (I/O-bound) — **полезна**.

Ведутся активные дискуссии о включении многопоточного интерпретатора в стандартную поставку.

## 22. Многопоточность для операций ввода-вывода. Пример `threads1fun`

Помимо CPU-задач, есть задачи **ввода-вывода**, которые часто очень медленные:
- ожидание чтения файла;
- ожидание пользовательского ввода;
- скачивание страницы из интернета;
- доступ к базе данных.

Пока один поток ждёт завершения операции ввода-вывода, другие потоки могут выполнять свою работу.

> **Многопоточность CPython имеет смысл использовать для операций ввода-вывода и не имеет смысла для вычислений.**

## 23. Потоки-демоны (daemon threads)

> **Поток-демон (daemon thread)** — поток, который **автоматически завершается** при завершении главного потока.

Пример: `threads1_class.py`.
- Класс `myThread` с атрибутами: `threadId`, имя, счётчик, признак демона.
- Если поток **не демон**: может пережить родительский (главный) поток.
- Если поток **демон**: принудительно завершается при завершении главного потока.

Термин «демон» пришёл из Linux/macOS. В Windows используется немного другая терминология.

> Если нужно автоматически завершать дочерние потоки при завершении родительского — объявляйте их демонами.

## 24. Глобальные переменные и потоки

- Все потоки в рамках одного процесса имеют доступ к **глобальным переменным**.
- Один поток может изменить глобальную переменную, другой увидит изменение.
- Для обмена данными достаточно глобальных переменных — никаких дополнительных средств не нужно.
- **Важно**: если переменная не объявлена как `global` внутри функции, она считается **локальной**, и другие потоки её не увидят. Необходимо явно использовать ключевое слово **`global`**.
- У каждого потока как объекта могут быть свои **атрибуты** (локальные для объекта). Обмен через атрибуты возможен, если разрешён доступ к атрибутам другого объекта или предусмотрены сеттеры.

## 25. Масштабирование: очереди. Пример `thread_files1` и `thread_files2_queues`

### Пример `thread_files1` — скачивание PDF без очередей
- Скачивание 5 PDF-файлов с сайта **IRS** (американское налоговое ведомство).
- Для каждого URL создаётся объект **`DownloadThread`** (наследник `threading.Thread`).
- Используется **`urllib.request`** для запросов по URL.
- **`urlopen`** открывает подключение, чтение идёт кусками по **1024 байта**, запись в локальный файл.
- 5 файлов скачиваются параллельно, общее время ≈ время самого медленного файла, а не сумма всех.

### Проблема масштабирования
- Чем больше потоков, тем меньше эффект: создание потока — дорогостоящая операция.
- Сотни и тысячи потоков нежелательны: потери на переключение контекста превышают выигрыш.

### Решение: архитектура «производитель — поставщик» с очередью

> **Очередь (Queue)** — структура данных из модуля **`queue`**, в которую складывается работа.

Пример `thread_files2_queues`:
- Создаётся объект **`Queue`**.
- Создаётся **5 потоков-исполнителей** (daemon-потоки).
- Каждый поток получает очередь, а не конкретный URL.
- В бесконечном цикле поток:
  1. Пытается получить работу из очереди (**`queue.get()`**). Если очередь пуста — блокируется и ждёт.
  2. Извлекает URL, запускает скачивание.
  3. После успешного скачивания подтверждает очереди (**`queue.task_done()`**), что задача выполнена.
  4. Возвращается к началу цикла за следующей работой.

Преимущества:
- **Балансировка нагрузки**: свободный исполнитель берёт следующую работу.
- **Масштабируемость**: можно поместить в очередь 500 URL, потоков остаётся 5.
- Нет ситуации, когда одному потоку достался большой файл, а другому маленький, и второй простаивает.

## 26. Многопроцессность. Модуль `multiprocessing`. Пример `multiprocessing01`

Для CPU-задач, где многопоточность CPython не помогает, используется **многопроцессность**.

> **Модуль `multiprocessing`** — библиотека для создания нескольких процессов из Python-процесса.

Пример `multiprocessing01`:
- Класс **`multiprocessing.Process`** — объект соответствует отдельному процессу.
- Код процесса задаётся через аргумент **`target`** (функция `child`).
- Функция `child`: задержка, печать **PID** процесса (подтверждение, что это отдельный процесс), ещё задержка, завершение.
- Создаётся 4 процесса. Всего в системе: 1 родительский + 4 дочерних = **5 процессов**, выполняющих один файл.

Наблюдение через Task Manager: видны 5 процессов с разными PID, по мере завершения они исчезают из списка.

## 27. Изоляция процессов и копии глобальных переменных

- У каждого процесса **свои глобальные переменные**.
- При создании нового процесса копируется окружение родительского процесса, включая глобальные переменные.
- Это **копия**: изменение глобальной переменной в одном процессе **не видно** в других.

Эксперимент: процесс с номером 0 меняет `MaxDelay` на 100, остальные процессы продолжают видеть значение 40.

> В отличие от потоков (общая память внутри процесса), процессы **не имеют общей памяти**. Для взаимодействия нужны IPC: семафоры, файлы, общая память, пайпы.

Файлы: одновременно писать в один файл может только один процесс — ОС не позволит двум процессам открыть один файл на запись одновременно.

## 28. AsyncIO. Общая идея

> **AsyncIO** — модуль для асинхронного ввода-вывода. Реализует сокрытие времени ожидания длительных операций ввода-вывода **без использования потоков**.

«Зонтичный термин»: включает также `AsyncHTTP` и другие модули с префиксом `Async`.

Так же, как и многопоточность, AsyncIO ускоряет только **операции ввода-вывода**, а не вычисления.

### Параллелизм vs одновременность
- **Истинный параллелизм** — только при многопроцессности (несколько процессов, каждый на своём ядре).
- **Иллюзия одновременности (конкуренция, concurrency)** — многопоточность и AsyncIO: пока один ждёт, выполняется другой.

### Основная идея AsyncIO
- Длительная операция **добровольно передаёт управление** другому коду, осознавая, что будет выполняться долго.
- Аналогия: стоя в очереди, отдать телефон тому, кто может им воспользоваться.
- Не нужно создавать несколько потоков — достаточно одной операции уступить управление.

### Синхронный vs асинхронный подход
- Синхронный: этапы последовательны, время суммируется (20 + 7 + 10 + 8 = 45 секунд).
- Асинхронный: этапы перекрываются, общее время ≈ самой длительной операции (20 секунд).

### Цикл запрос-ответ
- **Запрос** → **время ожидания** (ввод-вывод) → **ответ** → обработка.
- Жёлтые фрагменты — реальная работа Python-кода (процессор).
- Синие фрагменты — ожидание ввода-вывода.
- В асинхронной версии ожидания перекрываются: пока ждём ответ на первый запрос, отправляем второй, третий.

## 29. Цикл событий (event loop). Обработчики событий. Callback

> **Цикл событий (event loop)** — среда, отвечающая за диспетчеризацию и планирование событий. Определяет, какую операцию приостановить и какой дать выполниться.

> **Обработчик события** — содержит клиентский код (бизнес-логику), которую выполняет длительная операция.

> **Callback (функция обратного вызова, делегат обратного вызова)** — функция, которая уведомляет задачу о завершении длительной операции. После получения callback приостановленная задача возобновляет работу.

> **Yield point** — точка, в которой задача добровольно уступает управление и переходит в режим ожидания.

### Как работает цикл обработки событий
1. Главный поток передаёт задачи в цикл событий.
2. Цикл поддерживает **очередь задач** и мониторит её.
3. Выполняет задачи, пока не встретится операция с длительным ожиданием (помеченная `await`).
4. Диспетчер приостанавливает текущую задачу, возвращает управление ОС.
5. ОС инициирует операцию ввода-вывода.
6. По завершении ОС уведомляет диспетчер, диспетчер через callback уведомляет задачу.
7. Пока идёт ожидание, выбирается следующая задача из очереди.
8. Цикл повторяется.

Callback может быть простым (для обработчиков без состояния) или сложным (с сохранением состояния). Пример: `myHandler` принимает объект события и возвращает значение (например, 42).

## 30. Сопрограммы (coroutines). Ключевые слова async и await

> **Сопрограмма (coroutine)** — функция, которая может добровольно приостанавливать своё выполнение и затем возобновлять его после уведомления о завершении ожидания.

> **`await`** — ключевое слово, указывающее диспетчеру, что далее будет длительное ожидание, и задачу можно приостановить.

> **`async`** — ключевое слово, помечающее функцию как сопрограмму. Использовать `await` можно только внутри функции, помеченной `async`.

- `async` и `await` — **новые ключевые слова** в Python, добавленные с появлением AsyncIO. Это редкий случай, когда библиотека привела к изменению самого языка (не через декораторы).
- Любая функция с `await` называется сопрограммой.

### Версии и совместимость
- AsyncIO появился сравнительно недавно (примерно с версии **Python 3.9** перешёл из экспериментов в основную поставку).
- Модуль **продолжает меняться**, не полностью устоялся.
- В каждой версии Python появляются новые особенности AsyncIO.
- Код, написанный под AsyncIO 3.9, может не работать в 3.14.
- Всегда обращайте внимание, для какой версии Python написан пример.

## 31. Примеры AsyncIO. `asyncio01`

- Импорт модуля **`asyncio`**.
- Функция `foo` (сопрограмма, помечена `async`): засыпает на 1 секунду через **`await asyncio.sleep(1)`**. Возвращает 42.
- Функция `main` (сопрограмма): цикл из 10 итераций с ожиданием 1 секунды через `await`. Возвращает результат `foo`.
- Запуск: **`asyncio.run(main())`**.

> `asyncio.run()` — современный способ запуска цикла событий. Передаётся результат вызова сопрограммы (со скобками).

Старый способ (поддерживается, но устаревший):
- `asyncio.get_event_loop()` — получить объект цикла событий.
- `loop.run_until_complete(...)` — запустить на выполнение.

На временной диаграмме: поток один, но за счёт добровольной уступки (`await`) время ожидания заполняется выполнением другого кода.

### Пример из двух сопрограмм
- `main` запускает `say_after` дважды: с задержкой 1 секунда и «hello», с задержкой 2 секунды и «world».
- `say_after` уходит в ожидание, затем печатает параметр.
- Первым печатается «hello» (задержка 1 сек), затем «world» (задержка 2 сек).

### Запуск в IDE
- **Не рекомендуется** запускать AsyncIO-программы в IDE (Spyder, PyCharm): IDE сама использует AsyncIO для своих нужд, возникает конфликт («Event loop is already running»).
- Рекомендуется запускать в **чистом терминале**.

## 32. Пример: синхронный и асинхронный счётчик

### Синхронная версия
- Фиксируется время до и после.
- `main`: цикл из 3 итераций, каждая вызывает `count()`.
- `count()`: печатает 1, ждёт 1 секунду (`time.sleep(1)`), печатает 2, ждёт 1 секунду.
- Итого: 3 × 2 секунды = **6 секунд**.

### Асинхронная версия
- Импорт `asyncio`.
- Запуск: `asyncio.run(main())`.
- `main` помечена `async`.
- Три вызова `count()` раскладываются отдельно (вместо цикла), оборачиваются в **`asyncio.gather()`** — ожидание завершения всех трёх вызовов (аналог `join` для потоков).
- `count()` помечена `async`.
- `time.sleep(1)` заменяется на **`asyncio.sleep(1)`** — функция `sleep` из модуля `time` не поддерживает AsyncIO.
- Итого: ожидания перекрываются, общее время ≈ **2 секунды**.

> Экономия: пока один `count` ждёт, другие выполняют печать. Ожидания не суммируются, а перекрываются.

| **IPC (Inter-Process Communication)** | Средства межпроцессного взаимодействия |
| **Пайп (Pipe, конвейер)** | Средство IPC для последовательной передачи данных |
| **HPC (High Performance Computing)** | Высокопроизводительные вычисления |
| **Главный поток (MainThread)** | Первый поток процесса, выполняющий основной код |
| **Поток-демон (Daemon Thread)** | Поток, автоматически завершаемый при завершении главного потока |
| **GIL (Global Interpreter Lock)** | Механизм CPython, выполняющий код только одного потока в каждый момент |
| **Сопрограмма (Coroutine)** | Функция, способная приостанавливать и возобновлять выполнение |
| **Цикл событий (Event Loop)** | Среда диспетчеризации и планирования асинхронных задач |
| **Callback** | Функция обратного вызова, уведомляющая о завершении операции |
| **Yield Point** | Точка добровольной уступки управления |
| **`async` / `await`** | Ключевые слова Python для асинхронного программирования |
| **Очередь (Queue)** | Структура данных для организации работы по модели производитель-потребитель |
