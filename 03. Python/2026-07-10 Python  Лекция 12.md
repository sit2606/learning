## 3. Рекурсия: основы и последовательность Фибоначчи
**Рекурсия** — это вызов функцией самой себя (прямо или косвенно). Окружает нас в математике (натуральные числа определяются индуктивно) и быту.

### Последовательность Фибоначчи
* Математическое определение: первые два члена 0 и 1, каждый следующий — сумма двух предыдущих.
* *Альтернативное определение:* начинается с 1 и 1.
* Встречается в природе и искусстве.

### Базовое условие (Точка остановки)
Любая рекурсия должна иметь **базовый случай**, иначе возникнет бесконечный цикл и переполнение стека.
* Ошибка: `RecursionError: maximum recursion depth exceeded`.
* Каждый вызов функции создает фрейм (стек локальных переменных) в памяти. Бесконечная рекурсия съедает всю память.

**Пример базового условия для Фибоначчи:**
```python
def fib(n):
    if 0 <= n < 2:  # Python понимает двойное неравенство как в математике
        return n
    # Обработка отрицательных чисел (защита от внешнего вызова)
    if n < 0:
        raise ValueError("Последовательность определена только для неотрицательных n")
    return fib(n-1) + fib(n-2)
```

## 4. Проблема неэффективности рекурсии и Мемоизация

### Экспоненциальная сложность
При замерах времени выполнения `fib(28)` и `fib(36)` обнаруживается, что время растет не линейно, а по **экспоненте**.
* **Причина:** Алгоритм многократно вычисляет одни и те же значения (дерево рекурсивных вызовов содержит дубликаты).
* *Аналогия из лекции:* Физик и программист кипятят чайник. Программист предпочитает переиспользовать готовый алгоритм (рекурсию), даже если это кажется избыточным, но в случае с Фибоначчи это приводит к деградации.

> [!info] 🧠 Новое понятие: **Мемоизация (Memoization)**
> Техника в теории алгоритмов, заключающаяся в сохранении (кэшировании) результатов выполнения функций для предотвращения повторных вычислений. 
> *Не путать с memorization (заучивание наизусть).*

### Реализация мемоизации (Словарь-кэш)
```python
lookup_table = {}
def fib_memo(n):
    if 0 <= n < 2:
        return n
    if n in lookup_table:
        return lookup_table[n]
    
    # ОШИБКА, которую важно не допустить: нужно сохранить результат в кэш перед возвратом!
    lookup_table[n] = fib_memo(n-1) + fib_memo(n-2)
    return lookup_table[n]
```
*Исправленная мемоизация снижает время вычисления `fib(36)` до долей секунды.*

## 5. Итеративный подход и Хвостовая рекурсия

> [!note] 📌 Важное правило
> **Любую рекурсию можно заменить на цикл (итеративный алгоритм).** Если рекурсия кажется сложной или неэффективной — пишите цикл.

### Итеративный вариант Фибоначчи
Использование сдвига переменных (`a, b = b, a + b`). Работает быстро, не использует стек вызовов, но может упереться в лимит цифр целого числа в Python (по умолчанию 4300 цифр).

> [!info] 🧠 Новое понятие: **Хвостовая рекурсия (Tail Recursion)**
> Вид рекурсии, при котором рекурсивный вызов является *последней* операцией в функции. 
> * **Нехвостовая рекурсия:** после вызова нужно вернуться и выполнить действие (например, сложение или умножение). Стек растет.
> * **Хвостовая рекурсия:** возвращаться не нужно, результат передается дальше. Стек теоретически можно оптимизировать.
> * **Трюк с аккумулятором:** передача промежуточного результата через дополнительный параметр.

**Пример хвостовой рекурсии (Факториал):**
```python
def factorial_tail(n, accumulator=1):
    if n <= 1:
        return accumulator
    # Рекурсивный вызов передает накопленный результат
    return factorial_tail(n-1, n * accumulator) 
```
*Примечание:* Интерпретатор Python на данный момент **не оптимизирует** хвостовую рекурсию (в отличие от многих других языков), но знать этот концепт необходимо.

## 6. Косвенная рекурсия

> [!info] 🧠 Новое понятие: **Косвенная рекурсия**
> Ситуация, когда функция `A` вызывает функцию `B`, а функция `B` снова вызывает функцию `A` (цепочка из 2 и более звеньев).
> * Часто возникает случайно из-за опечаток.
> * Без базового условия приводит к бесконечному циклу и `RecursionError`.
> * Отлаживать такие ошибки очень сложно.

## 7. Безопасность и Хеширование паролей (bcrypt)

**История из практики:** Стартап обанкротился после утечки данных, потому что хранил пароли пользователей в **открытом тексте** (plain text) во внутренней базе. Это позволило хакерам использовать базы утекших паролей для брутфорс-атак на другие сервисы.

> [!warning] 🛑 Золотое правило безопасности
> **Никогда и нигде не храните пароли в открытом тексте.** Всегда используйте хэширование.

> [!info] 🧠 Новое понятие: **Хэш-функция**
> Одностороннее математическое сопоставление, преобразующее строку в уникальное значение (хэш).
> * **Отличие от шифрования:** Хэш нельзя обратить (восстановить исходную строку).
> * **Коллизии:** Разные строки могут дать одинаковый хэш, но вероятность этого для сильных алгоритмов ничтожно мала.

> [!info] 🧠 Новое понятие: **Соль (Salt)**
> Случайные данные, которые добавляются к паролю перед хэшированием. Защищает от криптографического анализа и использования готовых таблиц (rainbow tables).

### Библиотека `bcrypt`
* Устанавливается через `pip install bcrypt`.
* Работает с **байтовыми строками** (префикс `b"..."`), а не с обычными строками.

**Алгоритм работы:**
1. Генерация соли: `salt = bcrypt.gensalt()`
2. Хэширование при регистрации: `hash_val = bcrypt.hashpw(b"password", salt)`
3. Проверка при входе: `bcrypt.checkpw(b"entered_password", hash_val)`

## 8. Элементы функционального программирования в Python

> [!info] 🧠 Новое понятие: **Функциональное программирование (ФП)**
> Парадигма, в которой программа состоит исключительно из функций (пример языка **Lisp**). Нет переменных в привычном понимании, нет циклов `for/while`, нет `if/else` — только вызовы функций и математические вычисления.

Python — мультипарадигменный язык. В него внедрены элементы ФП.

> [!info] 🧠 Новое понятие: **Функции как объекты первого класса**
> С функциями можно делать всё то же, что и с данными:
> 1. Присваивать переменным (`f1 = func`).
> 2. Передавать в качестве аргументов.
> 3. Возвращать из других функций.

**Опасность переопределения:**
* *История из практики:* Студент написал `print = 10`. Встроенная функция `print` была перезаписана целым числом. Тесты преподавателя падали с ошибкой `TypeError: 'int' object is not callable`, так как модуль студента импортировался и ломал встроенный `print` для всей среды.
* *Правило:* Никогда не называйте переменные именами встроенных функций (`print`, `len`, `min`, `max`) или типов данных (`str`, `list`).

## 9. Функции высшего порядка (map, filter, zip, reduce)

> [!info] 🧠 Новое понятие: **Функция высшего порядка**
> Функция, которая принимает другую функцию в качестве аргумента или возвращает функцию в качестве результата.

> [!info] 🧠 Новое понятие: **Лямбда-функция (Lambda)**
> Анонимная функция без имени, состоящая только из одного выражения.
> *Синтаксис:* `lambda a, b: a + b`

> [!info] 🧠 Новое понятие: **Чистая функция**
> Функция без побочных эффектов. Она не меняет глобальные переменные и внешние объекты, а возвращает результат только на основе переданных аргументов.

### Встроенные функции высшего порядка:
1. **`map(func, iterable)`** — применяет функцию к каждому элементу коллекции.
   * *Пример:* `list(map(int, lst))` (анализ list comprehension).
2. **`filter(func, iterable)`** — фильтрует элементы, оставляя только те, для которых `func` вернула `True`.
   * *Пример:* `list(filter(lambda x: x > 0, lst))`.
3. **`zip(*iterables)`** — упаковывает элементы из нескольких списков в кортежи по индексам. Ориентируется на список меньшей длины.
4. **`reduce(func, iterable)`** — сворачивает последовательность в одно значение (находится в модуле `functools`).
   * *Пример:* `reduce(lambda a, b: a * b, lst)` (вычисление произведения).

## 10. Замыкания (Closures)

> [!info] 🧠 Новое понятие: **Замыкание**
> Замораживание контекста функции на момент её определения. Возможность вложенной функции использовать и "помнить" аргументы внешней функции даже после того, как внешняя функция завершила работу.

**Пример (параметризованная функция):**
```python
def multiplier(n):
    def mul(x):
        return x * n  # n "замораживается" здесь
    return mul

mul_by_3 = multiplier(3)
print(mul_by_3(5))  # Выведет 15
```
