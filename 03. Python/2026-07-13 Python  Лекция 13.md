## 1. Множественное наследование и проблема ромба
При множественном наследовании может возникнуть ситуация, когда у двух классов есть общий предок, а их общий потомок наследуется от обоих. Это называется ==**ромбовидным наследованием**==.
* **Проблема:** Возникает неоднозначность: атрибут или метод общего предка может быть унаследован по разным линиям с разными значениями. Сколько копий атрибута получит потомок и какую из них использовать?
* **Решение в разных языках:** 
  * В Java ромбовидное наследование запрещено во избежание этой проблемы.
  * В C++ и Python оно разрешено, но требует четких правил разрешения конфликтов.
* **Важно:** Наследование основывается на иерархии *классов*, а не конкретных *объектов*. Изменение атрибутов у существующих объектов предков не влияет на создаваемый объект-потомок.

## 2. Абстрактные классы и методы
==**Абстрактный класс**== – это класс, экземпляры которого не могут быть созданы (запрещена инстанциация). 
* **Зачем нужны:** Они участвуют в иерархии наследования, передавая потомкам методы и задавая общий интерфейс (поведение), но не предназначены для прямого использования.
* **Ручная имитация в Python:** Можно переопределить `__init__` или методы, выбрасывая исключение `raise NotImplementedError`. Однако это не запрещает создание экземпляра на уровне синтаксиса, ошибка возникнет только при вызове метода или конструктора.
* **Правильный способ в Python:** Использование встроенного модуля `abc`. Класс наследуется от `ABC`, а методы помечаются декоратором `@abstractmethod`.
* ==**Абстрактный метод**== – метод, который объявлен, но не имеет реализации (обычно содержит `pass`). Он заявляет поведение, которое *обязаны* реализовать все конкретные классы-потомки.
* **Нюанс:** В Python абстрактный метод *может* иметь реализацию. Однако, если класс-потомок не переопределит этот метод, он сам останется абстрактным, и создать его экземпляр будет нельзя.

## 3. Примеси (Миксины)
==**Миксин (Mixin)**== (или примесь) – это класс, который не предназначен для самостоятельного использования или создания экземпляров, а служит для добавления конкретной, изолированной функциональности другим классам через множественное наследование.
* **Пример:** Класс `MusicPlayerMixin` с методом `play_music`. Его можно "подмешать" к классам `Car`, `Tractor`, `Smartphone`, но не подмешивать к классу `Bicycle`, если велосипед не должен играть музыку. Это гибче, чем добавление метода в самый базовый класс иерархии.

## 4. Порядок разрешения методов (MRO)
==**MRO (Method Resolution Order)**== – это строгий порядок, в котором Python ищет атрибуты и методы в иерархии наследования.
* Определяется алгоритмом линеаризации C3.
* Можно просмотреть с помощью метода `ClassName.mro()` или атрибута `ClassName.__mro__`.
* **Правила:** 
  1. Поиск идет в порядке, указанном в кортеже базовых классов при объявлении.
  2. Инициализаторы (`__init__`) общих предков вызываются **только один раз**, несмотря на то, что предок может фигурировать в нескольких ветвях наследования.
  3. Порядок указания базовых классов в скобках `class D(B, C):` критически важен: `B` будет проверяться раньше, чем `C`.

## 5. Функции как объекты первого класса и замыкания
* В Python функции являются ==**объектами первого класса (first-class citizens)**==: их можно присваивать переменным, передавать как аргументы и возвращать из других функций.
* Функции могут быть определены локально внутри других функций.
* ==**Замыкание (Closure)**== – это функция, которая запоминает свое лексическое окружение (контекст и переменные внешней функции) даже после того, как внешняя функция завершила выполнение. Это фундаментальный механизм работы декораторов.

## 6. Декораторы функций и классов
==**Декоратор**== – это функция-обертка, которая изменяет или расширяет поведение другой функции или класса без изменения их исходного кода.
* **Синтаксис:** `@decorator_name` перед определением функции/класса.
* **Множественные декораторы:** Применяются по принципу "бутерброда" (или матрешки). Декоратор, ближайший к определению функции, применяется первым (внутренний слой), а самый верхний – последним (внешний слой).
* **Декораторы с аргументами:** Для создания универсальных декораторов используются `*args` (позиционные аргументы) и `**kwargs` (именованные аргументы), чтобы обернутая функция могла принимать любые параметры.
* **Модуль `functools`:** Декоратор `@wraps` из этого модуля рекомендуется использовать внутри декораторов, чтобы сохранять исходные метаданные (имя, докстринг) декорируемой функции.
* ==**Декоратор класса**==: позволяет применить логику обертки ко всему классу целиком. Например, можно автоматически пройтись по всем методам класса (исключая дандер-методы, начинающиеся с `__`) и обернуть каждый из них в логирование времени выполнения.

## 7. Метапрограммирование и Метаклассы
==**Метапрограммирование**== – это написание кода, который управляет, анализирует или генерирует другой код (или классы) во время выполнения программы.
* В Python всё является объектом, включая сами определения классов.
* ==**Метакласс**== – это класс, экземплярами которого являются другие классы. Базовым метаклассом в Python является `type`.
* **Динамическое создание классов:** Функция `type` может использоваться не только для проверки типа, но и для создания новых классов на лету: `type(name, bases, dict)`, где `name` – имя класса, `bases` – кортеж базовых классов, `dict` – словарь атрибутов и методов.

## 8. Дандер-методы __new__ и __call__
* ==**`__new__`**== – это истинный конструктор в Python. Он вызывается *до* `__init__` и отвечает непосредственно за **создание** (выделение памяти под) нового объекта. Переопределение `__new__` в метаклассе позволяет перехватывать и контролировать процесс создания классов или их экземпляров (например, запрещать создание экземпляров абстрактных классов или создавать финальные классы, запрещающие наследование).
* ==**`__call__`**== – дандер-метод, который определяет, можно ли вызвать объект как функцию. Если у объекта есть этот метод, он является вызываемым (`callable`). В Python методы – это по сути атрибуты, у которых присутствует `__call__`.
