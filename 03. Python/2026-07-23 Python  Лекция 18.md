## 2. Почему не работал импорт MessageBox

- Преподаватель ранее пытался использовать `import tkinter as tk`, а затем обратиться `tk.messagebox` — **не работало**.
- Причина: **`messagebox` — это не класс, а подмодуль (подпакет)** внутри `tkinter`.
- Написание строчными буквами (`messagebox`) — индикатор того, что это **имя модуля**, а не класса.
- При `import tkinter` подпакеты **не импортируются автоматически**. Нужно явно:
  ```python
  from tkinter import messagebox
  ```
- Соглашение: в Python 3 имена модулей записываются **строчными буквами**. Но не все библиотеки следуют соглашениям (пример: **Pillow** — модуль называется `PIL`).

> 🆕 **Новое понятие:** *подпакет (submodule/subpackage)* — вложенный модуль внутри пакета, который не импортируется автоматически при импорте родительского пакета.

## 4. Пример Hello World на Tkinter

Структура минимального приложения:

```python
from tkinter import *
from tkinter.ttk import *

window = Tk()
window.title("Добро пожаловать")

quit_btn = Button(window, text="Quit", command=quit)
quit_btn.place(x=50, y=50)

window.mainloop()
```

Ключевые элементы:
- Создание объекта `Tk()` — главное окно.
- Установка заголовка через `.title()`.
- Создание кнопки `Button` с параметром `command`.
- Размещение через `.place(x, y)` — фиксированные координаты.
- Запуск главного цикла `.mainloop()`.

## 7. События кнопки: command vs bind

### Параметр `command`
- Передаётся **ссылка на функцию** (без скобок!): `command=quit`, а не `command=quit()`.
- Функция-обработчик через `command` **не принимает параметров**.
- Автоматически объединяет **два события**:
  - Щелчок левой кнопкой мыши
  - Нажатие **пробела** при активном виджете (фокус через Tab)

### Метод `bind`
- Привязывает **конкретное событие** к обработчику.
- Функция-обработчик через `bind` **получает объект события** (`event`).
- Для аналогичного поведения нужно привязывать каждое событие отдельно.

### Фокус и Tab
- Виджеты можно активировать клавишей **Tab**.
- Активный виджет получает клавиатурные события.
- **Метки** исключены из обхода Tab (пассивный элемент).

## 8. Менеджеры размещения и mainloop

> 🆕 **Новое понятие:** *Менеджер размещения* — метод, определяющий положение виджета в родительском контейнере. Три варианта: **place**, **pack**, **grid**.

- **Без вызова менеджера размещения** виджет создаётся, но **не отображается**.
- **`mainloop()`** — цикл диспетчеризации событий. Без него программа создаёт объекты и сразу завершается, окно не рисуется.

### Менеджер `place`
- Размещение по **фиксированным координатам** (`x`, `y`).
- Виджет «прибит» к координатам, не перемещается при изменении размера окна.

## 9. Проблема глобальных переменных и классы как решение

### Проблема
- Функция `quit()` обращается к переменной `window` для вызова `destroy()`.
- Если код обёрнут в функцию `main()`, переменная `window` становится **локальной** и недоступна из `quit()`.
- Передать `window` как параметр в `quit()` нельзя, т.к. Tkinter сам вызывает обработчик без аргументов.

### Решение
- **Глобальные переменные** (работает, но не рекомендуется).
- **Классы**: методы класса общаются через **атрибуты объекта** (`self.parent`, `self.window` и т.д.).

## 10. Динамическое изменение шрифта виджетов

### Параметры шрифта
- Задаются **кортежем**: `("Helvetica", 8, "bold")`.
- Можно вынести в константу: `DEFAULT_FONT = ("Helvetica", 6)`.

### Изменение свойств виджета
Два способа:
1. **`widget.configure(font=new_font)`**
2. **`widget["font"] = new_font`** (индексирование)

### Важно
- Изменение переменной шрифта **не обновляет виджет автоматически**.
- Нужно **явно вызвать** `configure()` или присвоить через `[]`, чтобы виджет перерисовался.

### Консольный вывод в GUI
- `print()` в обработчиках выводит в консоль.
- Пользователь может **не увидеть** консоль (особенно если приложение запущено через `pythonw.exe`).

---

## 11. Ограничения менеджера place

- При увеличении шрифта кнопки **наезжают друг на друга**.
- Попытка вручную сдвинуть координату `x` через `place(x=...)` **не работает** как ожидается, если менять атрибут объекта.
- Координаты `x`, `y` в `place` считываются **в момент размещения**, не сохраняются как атрибут.
- Для получения реальной координаты: **`widget.winfo_x()`**.
- Перемещение виджета: **повторный вызов** `widget.place(x=new_x, y=new_y)`.

> 🆕 **Новое понятие:** *`winfo_x()` / `winfo_y()`* — методы виджета для получения текущих координат.

### Вывод
- Ручное управление координатами — **утомительно и ненадёжно**.
- Менеджеры размещения (`pack`, `grid`) делают это **автоматически**.

---

## 12. Переход к менеджеру pack

- Замена `place` на `pack` решает проблему наложения.
- `pack` **автоматически пересчитывает** размеры и позиции.
- Параметр **`side`**: `LEFT`, `RIGHT`, `TOP`, `BOTTOM` — расположение по сторонам света.
- По умолчанию `pack` выстраивает виджеты **в столбец сверху вниз**.

> ⚠️ **Важно:** для одного виджета использовать **только один** менеджер размещения. Смешивание `place` и `pack` приводит к конфликтам.

## 13. Пример 2: метки, текстовые поля, ComboBox

### Элементы
- **Label** (метка) — отображает текст, пассивный элемент.
- **Entry** (текстовое поле) — однострочный ввод.
- **Combobox** — выпадающий список.
- **Button** — кнопка.

### Особенности
- Размер окна задаётся **строкой**: `window.geometry("500x250")`.
- Менеджер **`grid`** — табличное размещение (строка, столбец).
- **`focus_set()`** — установка фокуса ввода на виджет.
- **`combobox.current(n)`** — выбор элемента по умолчанию (индексация с 0).
- **`combobox.get()`** — получение текущего значения.

### Обработчики
- Первая кнопка: `command=clicked1` (без параметров).
- Вторая кнопка: `bind("<Button-1>", str_to_sort_list)` (получает `event`).

### Объект события (`event`)
- Содержит информацию: тип события, координаты нажатия.
- Создаётся внутри Tkinter, **нельзя добавить свои атрибуты**.

### Изменение состояния виджета
- `label.configure(text=new_text)`
- `label["text"] = new_text`

### Важный урок
- Значение, сохранённое в переменную, **не обновляется автоматически**.
- Если нужно актуальное значение из виджета — вызывать `.get()` в момент использования.

## 14. Проблема лексикографической сортировки

- `split()` без параметров разбивает по **пробельным символам**.
- Сортировка строк — **лексикографическая** (как в словаре):
  - `"0100" < "1" < "100" < "2"`
- Для числовой сортировки нужно преобразовать в `int`:
  ```python
  sorted([int(x) for x in parts])
  ```
- Можно использовать **f-строки** вместо `.format()` — функционально эквивалентны.

## 15. Пример 3: RadioButton и MessageBox

> 🆕 **Новое понятие:** *RadioButton* — переключатель (радиокнопка). Группа радиокнопок, из которых можно выбрать только одну.

### RadioButton
- Связывается с переменной **`IntVar()`** (или `StringVar()`).
- Параметр **`variable`** объединяет кнопки в **группу**.
- Параметр **`value`** — значение, присваиваемое переменной при выборе.
- Отображаемый текст и внутреннее значение **независимы**.
- Метод **`.set()`** — программный выбор элемента по умолчанию.
- По умолчанию может быть **ничего не выбрано**.

### MessageBox
- **`messagebox.askquestion()`** — диалог с кнопками Yes/No.
- Возвращает `"yes"` или `"no"`.
- Разновидности: `showerror`, `showwarning`, `showinfo`, `askquestion`, `askyesnocancel`.

### Наращивание текста в метке
```python
label["text"] = label["text"] + new_text
```

## 16. Пример 4: текстовая область и привязка Enter

### Элементы
- **Entry** — однострочное текстовое поле.
- **Text** — многострочная текстовая область.
- Параметры Text: `width`, `height`, `font`, `bg`, `fg`, `wrap=WORD`.

> 🆕 **Новое понятие:** *`wrap=WORD`* — перенос текста по целым словам в многострочной области.

### Привязка событий
- Одна функция-обработчик может быть привязана к **нескольким событиям**.
- Используется параметр по умолчанию `event=None`, чтобы функция работала и через `command` (без аргументов), и через `bind` (с аргументом).

### Четыре события на один обработчик
1. Щелчок мышью по кнопке (через `command`)
2. Tab → кнопка → пробел (через `command`)
3. Tab → кнопка → Enter (через `bind` на кнопке)
4. Enter в любом месте окна (через `bind` на окне)

### Методы Text
- **`text.delete("1.0", END)`** — удалить всё содержимое.
- **`text.insert(END, new_text)`** — вставить в конец.

### Замечание
- Если Text не предназначена для редактирования — ставить **read-only**.
- Enter в Text перехватывается обработчиком → невозможно ввести многострочный текст обычным способом.

## 17. Пример 5: мышиные события и фрейм

> 🆕 **Новое понятие:** *Frame (фрейм)* — контейнер для организации интерфейса. Может быть невидимым, если не заданы границы.

### Структура
- Фрейм создаётся для организации интерфейса.
- Кнопка размещается **в главном окне**, а не во фрейме.
- Порядок вызовов `pack()` **важен**: определяет взаимное расположение.

### Обработчики
- **Enter** на окне → смена цвета фона фрейма.
- Цвета переключаются через перестановку элементов списка.
- **Мышиные события** на главном окне:
  - `<Button-1>` — левая кнопка
  - `<Button-3>` — правая кнопка
  - `<Motion>` — движение мыши
- Меняют **заголовок окна**.

### Перехват событий
- Если событие происходит над **дочерним элементом** и у него есть обработчик — дочерний перехватывает.
- Если у дочернего нет обработчика — событие **всплывает** до родителя.

## 18. Пример 6: оформление приложения в виде класса

### Структура класса
```python
class Example(Frame):
    def __init__(self, parent):
        super().__init__(parent)
        self.parent = parent
        self.initUI()

    def initUI(self):
        self.parent.title("...")
        # создание и размещение виджетов
```

- Класс наследуется от **`Frame`**.
- Обязательно вызвать `super().__init__()`.
- Ссылка на родительское окно сохраняется в **`self.parent`**.
- **`initUI()`** — метод для создания всех виджетов (не зарезервированное имя, но общепринятое).

### Guard для импорта
```python
if __name__ == "__main__":
    main()
```
Позволяет импортировать модуль без запуска приложения.

### Позиционирование окна
- `window.geometry("300x200+100+100")` — размер + координаты на экране.
- Можно программно запросить разрешение экрана и скорректировать.

## 19. Стили TTK

> 🆕 **Новое понятие:** *Стили TTK* — механизм оформления виджетов, аналогичный **CSS**. Позволяет создавать темы, переключаться между ними.

```python
from tkinter.ttk import Style
style = Style()

```

- Темы можно **настраивать** и **создавать свои**.
- Можно предоставить пользователю выбор из нескольких тем.

### Пример 6a

- Метод `quit()` получает доступ к родительскому окну через `self.parent`.

## 20. Пример 7: вложенные фреймы

### Иерархия
```
root (Tk)
 └── Example (Frame)
      ├── Frame1
      │    ├── Label ("Title")
      │    └── Entry
      ├── Frame2
      │    ├── Label ("Author")
      │    └── Entry
      └── Frame3
           ├── Label ("Review")
           └── Text
```

### Размещение
- Внешний фрейм: `pack(fill=BOTH, expand=True)` — занимает всю площадь.
- Внутренние фреймы: `pack(fill=X)` — максимальная ширина.
- Метка "Review": `pack(side=LEFT, anchor=N)` — привязка к северной границе.
- Текстовая область: `pack(fill=BOTH, expand=True)`.

### Вывод
- Фреймы позволяют **комбинировать** разные параметры размещения.
- Один `pack` на уровне фреймов, но разные параметры внутри каждого.

## 21. Эскизы интерфейса в draw.io

### Методика
1. Нарисовать макет окна в **draw.io** (или аналогичном инструменте).
2. Обвести группы элементов прямоугольниками без заливки.
3. Разные цвета/стили линий = разные менеджеры размещения.
4. Подписать параметры (`side=LEFT`, `fill=X` и т.д.).

def draw_triangle(self, vertices, depth):

        midpoints = compute_midpoints(vertices)
