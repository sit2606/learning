## Лекция 8 (29.06) — Введение в ООП

### Зачем нужен ООП

В процедурном подходе данные и функции разделены. Эволюция структур данных:

1. **Список списков** — неудобно, доступ только по индексу, нужно помнить порядок полей.
2. **Список словарей** — лучше, доступ по ключам (`market['city']`), но поиск рынка по ID требует полного перебора (медленно).
3. **Словарь словарей** — ключ — `FMID`, значение — словарь с данными. Быстрый поиск по ID. Для частого поиска по индексу (ZIP) создаются «параллельные словари» (индексы).

**Главная проблема процедурного подхода:** данные и функции их обработки разделены. Ничто не мешает случайно использовать глобальные переменные, код становится сложным для отслеживания.

**Решение — ООП:** упаковка данных и методов работы с ними в единое целое (Класс).

> Человек воспринимает мир как объекты, обладающие атрибутами (свойствами) и поведением (методами).

**Абстракция** — выделение только существенных свойств (в БД кадров не нужно знать количество костей, а в патологоанатомической — не нужно знать хобби).

**Этапы:** ОО-анализ → ОО-проектирование (UML) → ОО-программирование.

## Лекция 9 (01.07) — Классы, объекты, self, SOLID

### Классы и объекты

- **Класс** — чертеж, описание модели (как функция `def`, но для объектов).
- **Экземпляр класса (Объект)** — конкретная реализация класса с данными.

**Соглашение об именах:**
- Классы: **PascalCase** (`StudentGrade`)
- Функции/переменные: **snake_case** (`student_grade`)

**Создание объекта:**
```python
person1 = Person()
```

**Идентификатор объекта (`id()`):**
- `id(obj)` — уникальный идентификатор в памяти
- `hex(id(obj))` — адрес в hex-формате
- `id(a) == id(b)` → обе переменные ссылаются на **один и тот же объект**
- Инструмент для визуализации: **Python Tutor**

### Атрибуты (Состояние)

- Атрибуты можно создавать «на лету» (`person1.name = "Mike"`)
- Объекты одного класса могут иметь **разный набор** атрибутов
- Несуществующий атрибут → `AttributeError` (проявление Duck Typing)
- Удаление: `del person1.age`

### Методы (Поведение)

- Функция внутри класса — **метод**
- **`self`** — неявный первый параметр любого метода, ссылка на сам объект
- Если забыть `self` → ошибка `takes 1 positional argument but 2 were given`

### Атрибуты класса vs атрибуты экземпляра

- **Атрибут класса** (`ClassName.var`) — общий для всех, один экземпляр на весь класс
- **Атрибут экземпляра** (`self.var`) — уникален для каждого объекта

**Правила разрешения имен:**
- Если у экземпляра нет атрибута, Python ищет его на уровне класса (Resolution Order)
- Присвоение `self.attr = val` создаёт атрибут экземпляра, который «затеняет» атрибут класса

**Пример со счётчиком объектов:**
```python
class Person:
    count = 0  # атрибут класса

    def __init__(self):
        Person.count += 1
```

### Статические методы

Метод без `self`, вызывается от имени класса:
```python
def getCount():
    return Person.count

Person.getCount()  # вызов от класса
```
Ошибка: `Person().getCount()` — Python попытается передать объект как первый аргумент.

### SOLID и базовые принципы

**Open-Closed Principle (Бертран Мейер):**
Система должна быть открыта для расширения и закрыта для модификации. Чтобы добавить новую функциональность, не нужно переписывать старый код.

**Liskov Substitution Principle:**
Объекты родительского класса можно заменить объектами дочернего класса без нарушения правильности работы программы.

> Если что-то выглядит как утка, квакает как утка, но требует батареек — ваша абстракция неверна.

**Duck Typing (Утиная типизация):**
Тип объекта определяется не наследованием, а поведением. Python проверяет наличие нужного метода, а не принадлежность к классу.

## Лекция 10 (02.07) — Наследование, __init__, магические методы, инкапсуляция

### Наследование от `object`

Если предок не указан, класс наследуется от `object` по умолчанию. Класс `object` содержит базовый метод `__str__` для представления объекта в виде строки. Мы можем **переопределить** его.

### Магические методы (Dunder methods)

Методы с именами `__name__` (от *double underline*). Переопределяя `__str__`, мы заставляем `print` использовать нашу логику:
```python
def __str__(self):
    return f"Person: {self.name}, age {self.age}"
```

Переопределение метода в потомке не затрагивает предка — потомок получает *копию* навыка и может её изменить.

### Инициализатор `__init__`

```python
def __init__(self, objName="", objAge=0):
    self.name = objName
    self.age = objAge
```

- Вызывается сразу после создания объекта для настройки атрибутов
- Строго говоря, это не конструктор (конструктор — `__new__`), а инициализатор, но в литературе его часто называют конструктором
- Параметры по умолчанию не ломают старый код

### Наследование и `super()`

**Суперкласс (родитель)** — класс, от которого наследуются свойства. **Подкласс (потомок)** — класс, который наследует.

- Предок всегда проще/general, потомок специализирован + что-то новое
- **Инициализатор предка НЕ вызывается автоматически** — нужен `super().__init__()`

```python
class Student(Person):
    def __init__(self, objGroup, objName="", objAge=0):
        super().__init__(objName, objAge)
        self.group = objGroup
```

`super()` — ссылка на объект класса-предка, позволяет вызывать методы без жёсткой привязки к имени.

### Жизненный цикл объекта

```
__new__ → __init__ → работа объекта → __del__ (сборщик мусора)
```

- **`__new__`** — истинный конструктор (создаёт объект)
- **`__init__`** — инициализатор (настраивает атрибуты)
- **`__del__`** — деструктор, вызывается при уничтожении сборщиком мусора
- Недетерминированность: нельзя точно предсказать, когда сработает `__del__`
- Деструктор предка **не вызывается автоматически** — нужен `super().__del__()`

### Магические методы (сводка)

| Группа | Методы |
|--------|--------|
| Создание/удаление | `__new__`, `__init__`, `__del__` |
| Числовые/арифметические | `__add__` (+), `__sub__` (-), `__mul__` (*), `__truediv__` (/), `__mod__` (%), `__abs__`, `__neg__` (унарный -) |
| Строковые | `__str__` (для print), `__repr__` (техническое представление) |
| Сравнение | `__eq__` (==), `__ne__` (!=) |
| Прочее | `__len__` (len()), `__dir__` (dir()) |

**Пример реализации сложения:**
```python
def __add__(self, other):
    return Person(self.name + other.name, 0)
```

### Сравнение объектов

- `is` — сравнивает **ссылки** (одна ячейка памяти?)
- `==` — должно сравнивать **состояние**, но для кастомных классов нужно настраивать через `__eq__`

```python
def __eq__(self, other):
    return self.name == other.name and self.age == other.age
```

### Рефлексия и управление атрибутами

**Словарь `__dict__`:**
- У каждого экземпляра есть `__dict__` — словарь всех атрибутов
- Через него можно читать, добавлять и удалять атрибуты напрямую
- У класса тоже есть `__dict__`, но отображается как `mappingproxy` (только чтение)

**Встроенные функции:**
- `hasattr(obj, 'name')` — проверка наличия атрибута
- `getattr(obj, 'name')` — получение значения
- `setattr(obj, 'name', val)` — установка/изменение атрибута

### Инкапсуляция

Один из трёх китов ООП (наряду с наследованием и полиморфизмом). Механизм защиты внутреннего состояния объекта. Разделение на **публичный интерфейс** и **приватную реализацию**.

**1. Name Mangling** — атрибуты с двойным подчёркиванием (`__count`) считаются приватными. Python переименовывает в `_ClassName__count`. Защита «от честных людей».

**2. `@property` — свойства (getters/setters):**
```python
@property
def age(self):
    return self.__age

@age.setter
def age(self, value):
    if 1 <= value <= 99:
        self.__age = value
    else:
        print("Недопустимый возраст")
```

- Синтаксис обращения как к атрибуту: `person.age` (без скобок)
- Только getter → **read-only**, только setter → **write-only**
- Проверка допустимости значений, преобразование величин, будущая расширяемость

### Перегрузка функций

В Python **НЕ поддерживается** (позднее определение перетирает предыдущее).

Альтернативы:
- Параметры по умолчанию: `def f(a, b, c=1)`
- Произвольное количество аргументов: `def f(*args)`
- `math.prod(iterable)`

### Класс как объект

- Имя класса — идентификатор (переменная), указывающая на объект класса
- Классу можно присвоить алиас: `AnyPerson = Person`
- Класс можно переопределить: `Person = 10` (создание экземпляров станет невозможно)

## Лекция 11 (06.07) — Связность, IS-A/HAS-A, LSP, полиморфизм

### Зависимости и связность (Coupling)

**Зависимость (Dependency)** — любое отношение между двумя классами, всегда **однонаправленное**. Если A зависит от B, изменение B может сломать A.

- **High Coupling (высокая связность)** — плохо: изменение одного класса требует изменения всех остальных
- **Low Coupling (низкая связность)** — цель проектирования

**Математика зависимостей:**
- 2 класса → максимум 2 зависимости
- 3 класса → максимум 6
- n классов → максимум **n·(n−1)** → рост **O(n²)**

> При увеличении числа компонентов в 2 раза сложность растёт в 4 раза. Именно зависимости «убивают» сложные системы.

### Наследование (IS-A)

```python
class Student(Person):  # Student IS-A Person
```

Примеры IS-A:
- Медведь **является** млекопитающим
- Дом **является** недвижимостью

**Контрпримеры (НЕ IS-A):**
- Машина ≠ двигатель — здесь отношение HAS-A

### Принцип подстановки Барбары Лисков (LSP)

Экземпляр потомка должен **всегда и без проблем** подставляться вместо предка.

**Классический пример: Circle vs Ellipse**

| Вариант | Вердикт | Причина |
|---------|---------|---------|
| Ellipse → Circle | ❌ | Наследник получает лишний параметр y, который надо держать равным x |
| Circle → Ellipse | ❌ | Формула площади окружности π·r² неверна для эллипса (нужно π·a·b) |
| Оба от `Shape` | ✅ | Общий предок, между собой не связаны наследованием |

> То, что верно в школьной геометрии, не всегда верно в ООП-моделировании.

**Point2D и Circle** — корректное наследование. Любую окружность можно представить как «раздутую точку» с радиусом.

### `__repr__` vs `__str__`

- `__str__` — **дружественное** представление для пользователя (print)
- `__repr__` — **техническое/низкоуровневое** представление (все детали состояния)

### HAS-A: Ассоциация, Агрегация, Композиция

**Ассоциация** — зонтичный термин для любых отношений «вхождения».

| Тип | Определение | UML |
|-----|-------------|-----|
| **Агрегация** | Слабая ассоциация; объект-часть может существовать **отдельно** от контейнера | Пустой ромб |
| **Композиция** | Сильная ассоциация; при уничтожении контейнера **уничтожаются и все части** | Закрашенный ромб |

**Агрегация (пример Employee и Salary):**
```python
salary = Salary(100000)
emp = Employee(salary, bonus=10000000)
```
- `Salary` создаётся **отдельно** от `Employee`
- Одну зарплату можно дать разным сотрудникам
- Сотрудник может существовать **без** зарплаты

**Композиция:**
```python
class Employee:
    def __init__(self, monthly_pay, bonus):
        self.salary = Salary(monthly_pay)  # создаётся ВНУТРИ
```
- `Employee` **сам создаёт** свою `Salary`
- Два сотрудника **не могут** разделять одну зарплату
- При уничтожении `Employee` уничтожается и его `Salary`

**Как перейти от агрегации к композиции:**
- Агрегация: объект-часть передаётся в `__init__` извне
- Композиция: объект-часть **создаётся внутри** `__init__` контейнера

**Пример из жизни:**
- Колёса — агрегация (можно снять и поставить на другую машину)
- Кузов — композиция (практически никогда не переставляется)

### Полиморфизм функций

```python
def add(a, b):
    return a + b
```

Работает с: `int + int`, `float + float`, `str + str` (конкатенация), `list + list` (объединение), `Point2D + Point2D`.

**Единственное требование:** для типа определена операция `+` (`__add__`).

- ✅ Гибкость — одна функция для многих типов
- ❌ Неявность требований — по коду нельзя сразу понять, какие типы допустимы

### Передача параметров

В Python — **по присваиванию**. Фактически происходит `локальная_переменная = переданное_значение`. Все параметры функции — локальные переменные.

### Возврат нескольких значений

```python
return a, b, c   # упаковка в кортеж
x, y, z = func() # автоматическая распаковка
```

## Лекция 12 (08.07) — Завершение ООП: спецификация, инвариант, абстракция

### Продвинутые концепции ООП

Лектор завершил тему ООП, обсудив формальные концепции:

**Спецификация (Specification):**
Формальное описание контракта класса — что делает каждый метод, какие предусловия и постусловия должны выполняться.

**Инвариант представления (Representation Invariant):**
Условие, которое **всегда** должно выполняться для корректного состояния объекта. Если инвариант нарушен — объект в недопустимом состоянии. Пример: в стеке внутренний список не должен быть `None`.

**Функция абстракции (Abstraction Function):**
Отображение внутреннего состояния объекта в его абстрактное/пользовательское значение. Связывает, как конкретные поля класса соотносятся с тем, что видит пользователь.
