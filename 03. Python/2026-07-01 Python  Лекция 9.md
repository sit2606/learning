## 1. Повторение: CSV, DictReader и генерация словарей
*   **`DictReader`** позволяет прочитать CSV-файл и представить его в виде **списка словарей**, где каждая строка файла становится отдельным словарем. Это крайне удобный и распространенный формат.
*   **Dictionary Comprehension (Генерация словарей)**: аналог List Comprehension, но для словарей. Использует фигурные скобки `{}`. Позволяет из списка словарей сделать «словарь словарей».
    *   *Пример:* использование значения `name` в качестве ключа внешнего словаря, а всей строки (строки CSV) — в качестве значения.
*   **Метод `pop()`**: позволяет извлечь значение по ключу и **одновременно удалить** эту пару ключ-значение из словаря. Полезно, чтобы избежать дублирования данных (например, когда ключ внешнего словаря и так уже хранится внутри внутреннего).
*   *Правило работы со словарями:* искать по ключу — быстро и дешево. Искать по значению (не зная ключа) — дорого и медленно.

> **🟢 Новое понятие:** **Dictionary Comprehension** — механизм генерации словарей в одну строку с использованием цикла и условия внутри фигурных скобок.

## 2. Формат данных JSON
**JSON (JavaScript Object Notation)** — формат обмена данными, изначально созданный в JavaScript, но идеально ложащийся на структуры данных Python (списки и словари).

*   **Модуль `json`** в Python:
    *   `json.dump(obj, file)` — записывает объект в файл.
    *   `json.load(file)` — читает объект из файла.
    *   `json.dumps(obj)` — преобразует объект в **строку** (string).
    *   `json.loads(string)` — парсит **строку** в объект Python.
*   **Параметры записи:**
    *   `ensure_ascii=False` — разрешает использование Unicode (кириллицы), иначе не-ASCII символы будут экранироваться.
    *   `indent=4` (или 2) — количество пробелов для отступов. Влияет *только* на визуальное восприятие файла человеком, на чтение кодом не влияет.
*   **Кодировка:** файлы с не-ASCII символами (кириллицей) нужно открывать на чтение/запись с указанием `encoding='utf-8'`.

> **🟢 Новое понятие:** **JSON (JavaScript Object Notation)** — текстовый формат обмена данными, основанный на структурах словарей и списков.

## 3. Разметка Markdown и Jupyter Notebooks
Обычный `.py` файл не сохраняет результат выполнения кода. Для создания интерактивной документации, сохраняющей код, его вывод и форматированный текст, используются **Jupyter Notebooks** и разметка **Markdown**.

### Основы Markdown (`.md`)
*   **Заголовки:** `#` (1 уровень), `##` (2 уровня), `###` (3 уровня). Альтернатива для 1 и 2 уровня — подчеркивание `===` и `---`.
*   **Форматирование:** `*курсив*`, `**полужирный**`.
*   **Цитаты:** `> текст цитаты`.
*   **Код:**
    *   Внутри строки: обратная типографская кавычка (backtick) `` `код` ``. Отображается моноширинным шрифтом (например, Courier).
    *   Блок кода: три backtick'а ``` до и после кода. Сохраняет все отступы и переносы строк.
*   **Ссылки:** `[Текст ссылки](URL)`
*   **Изображения:** `![Альтернативный текст](путь_к_файлу.png)`
*   **Таблицы:** создаются с помощью вертикальных `|` и дефисов `-`.
*   **Списки:** маркированные (`-` или `*`) и нумерованные (`1.`). Поддерживаются многоуровневые списки (через отступы/Tab).
*   **Индексы:** `H~2~O` (подстрочный), `X^2^` (надстрочный).
*   *Инструменты:* Notepad++ (плагин Markdown Panel), Typora, VS Code (встроенный Preview).

### Jupyter Notebook (`.ipynb`)
Файл ноутбука внутри себя представляет собой **JSON-структуру**, содержащую список ячеек (`cells`).
*   **Типы ячеек:** Markdown (для текста) и Code (для Python).
*   **Выполнение:** `Shift + Enter` (выполнить ячейку и перейти к следующей).
*   **Состояние:** Notebook сохраняет `outputs` (вывод) прямо в файл. Можно передать файл другому человеку, и он увидит результаты без повторного запуска кода.
*   **Нумерация:** `[5]` в квадратных скобках показывает порядок выполнения ячеек.

> **🟢 Новое понятие:** **Markdown** — облегченный язык разметки для форматирования текста.
> **🟢 Новое понятие:** **Jupyter Notebook** — интерактивная среда, позволяющая объединять код, его результат, текст (Markdown) и мультимедиа в одном документе.

## 4. Магические команды Jupyter и моржовый оператор
В ноутбуках доступны **Magic Commands** для взаимодействия с ОС и расширения возможностей Python.

*   **Магические команды:**
    *   `%lsmagic` — список всех доступных магических команд.
    *   `%%writefile filename.py` — создает файл и записывает в него содержимое ячейки.
    *   `!dir` (или `!ls`) — выполнение команд терминала/ОС (восклицательный знак).
    *   `%timeit` — измеряет время выполнения кода (запускает несколько раз для вычисления среднего и стандартного отклонения).
*   **Моржовый оператор (Walrus operator) `:=`**
    *   Обычный оператор присваивания `=` нельзя использовать внутри выражений (например, `a = (b = 5)` вызовет ошибку).
    *   Моржовый оператор `:=` позволяет присваивать значение переменной **внутри выражения** и возвращать это значение.
    *   *Пример:* `print(d := 66)` выведет 66 и присвоит переменной `d` значение 66.

> **🟢 Новое понятие:** **Magic Commands** — специальные команды Jupyter, начинающиеся с `%` или `!`, для управления средой, ОС и файлами.
> **🟢 Новое понятие:** **Моржовый оператор (`:=`)** — оператор присваивания внутри выражения.

## 5. Предпосылки к ООП: связь данных и поведения
Если данные (JSON/словари) и функции (обработка данных) существуют раздельно, возникает проблема: **нет гарантии, что функция работает с правильными данными**. Любая функция имеет доступ к любым данным, что затрудняет поддержку больших проектов.

**Решение ООП:** объединить данные и средства работы с ними в одно целое.
*   **Состояние (State)** — набор атрибутов (данных) объекта.
*   **Поведение (Behavior)** — набор методов (функций), которые могут изменять состояние или выполняться над объектом.

> **🟢 Новое понятие:** **Объект** — сущность, обладающая четкими границами, состоянием (атрибуты) и поведением (методы).
> **🟢 Новое понятие:** **ООП (Объектно-Ориентированное Программирование)** — парадигма, где программа представляется как совокупность взаимодействующих объектов, а не как набор функций.

## 6. Базовые принципы ООП и SOLID
### Принцип открытости-закрытости (Open-Closed Principle)
*Автор: Бертран Мейер.*
Система должна быть **открыта для расширения** и **закрыта для модификации**.
*   *Суть:* Чтобы добавить новую функциональность (например, новую фигуру в графический редактор), не нужно переписывать старый, уже работающий код.
*   *Мем из лекции:* «Чтобы надеть пальто, не нужно делать полостную операцию на грудной клетке».

### Принцип подстановки Барбары Лисков (Liskov Substitution Principle)
Объекты родительского класса можно заменить объектами дочернего класса без нарушения правильности работы программы.
*   *Мем из лекции:* «Если что-то выглядит как утка, квакает как утка, но требует батареек — ваша абстракция неверна». Пластмассовую утку нельзя подставить вместо живой, так как система сломается (потребуются батарейки).

### Duck Typing (Утиная типизация)
В Python (с его динамической типизацией) тип объекта определяется не его наследованием, а его поведением.
*   *Правило:* «Если это выглядит как утка, плавает как утка и крякает как утка, то это утка».
*   Интерпретатор Python проверяет не тип переменной, а **наличие нужного метода** у объекта в момент вызова.

> **🟢 Новое понятие:** **Duck Typing (Утиная типизация)** — подход в динамически типизированных языках, при котором проверяется наличие определенных методов/свойств у объекта, а не его принадлежность к конкретному классу.
> **🟢 Новое понятие:** **SOLID** — акроним пяти основных принципов ООП (Single Responsibility, Open-Closed, Liskov Substitution, Interface Segregation, Dependency Inversion).

## 7. Важные концепции Computer Science (Тьюринг, P vs NP)
*Лектор отметил важность общего кругозора в Computer Science.*
*   **Премия Тьюринга** — высшая награда в области компьютерных наук (аналог Нобелевской премии). Названа в честь Алана Тьюринга.
*   **Машина Тьюринга** — математическая модель вычислительной машины, предложенная в 1930-х годах.
*   **Тест Тьюринга** — тест на наличие у машины искусственного интеллекта (General AI).
*   **Проблема P vs NP** — фундаментальная неразрешенная проблема (входит в список задач тысячелетия Института Клея с призом в $1 млн).
    *   **P** — задачи, решаемые за полиномиальное время (быстро).
    *   **NP** — задачи, проверяемые за полиномиальное время (но не обязательно решаемые быстро).
    *   *Вопрос:* Равны ли эти классы задач? (Интуиция подсказывает, что P ≠ NP, но доказательства нет).

## 8. Классы и объекты в Python
*   **Класс** — это чертеж, описание модели (как функция `def`, но для объектов).
*   **Экземпляр класса (Объект)** — конкретная реализация класса с данными.
*   **Соглашение об именах:**
    *   Классы: **PascalCase** (каждое слово с заглавной буквы, например, `StudentGrade`).
    *   Функции/переменные: **snake_case** (нижние подчеркивания, например, `student_grade`).
*   **Создание объекта:** `person1 = Person()`
*   **Идентификатор объекта (`id()`):**
    *   `id(obj)` возвращает уникальный идентификатор объекта в памяти (производная от адреса памяти).
    *   `hex(id(obj))` покажет адрес в шестнадцатеричном формате (совпадает с тем, что выводится при `print(obj)`).
    *   Если `id(obj1) == id(obj2)`, значит, это **ссылки на один и тот же объект** в памяти.
    *   *Инструмент для визуализации:* **Python Tutor**.

> **🟢 Новое понятие:** **Класс** — шаблон для создания объектов, определяющий их начальные атрибуты и методы.
> **🟢 Новое понятие:** **Экземпляр класса (Instance)** — конкретный объект, созданный по чертежу класса.

## 9. Атрибуты, методы и ключевое слово self
### Атрибуты (Состояние)
*   В Python атрибуты можно создавать «на лету» для уже существующих объектов (`person1.name = "Mike"`).
*   Объекты одного класса могут иметь **разный набор атрибутов** (у одного есть `age`, у другого нет).
*   Попытка прочитать несуществующий атрибут вызывает ошибку **`AttributeError`** (это и есть проявление Duck Typing: интерпретатор «спрашивает» у объекта, есть ли у него такой атрибут).
*   **Удаление атрибутов:** ключевое слово `del` (`del person1.age`). Также работает для удаления переменных и пар из словарей.

### Методы (Поведение)
*   Функция, определенная **внутри класса**, называется методом.
*   **Проблема:** как метод поймет, с каким именно объектом ему работать?
*   **Решение (`self`):** При вызове метода от имени объекта (`person2.inc_age(5)`), Python **неявно** передает ссылку на сам объект в качестве **первого аргумента**.
*   По соглашению этот неявный первый параметр называется **`self`**.
    *   *Ошибка:* `takes 1 positional argument but 2 were given` — возникает, если забыть указать `self` в определении метода. Python передал объект неявно, но метод его не принял.

### Атрибуты класса (Значения по умолчанию)
*   Если задать переменную прямо в теле класса (`class Person: age = 0`), она станет **атрибутом класса**.
*   Все вновь создаваемые объекты будут наследовать это значение по умолчанию, если оно не будет перезаписано для конкретного экземпляра.
*   *Важно:* В Python нет жесткой инкапсуляции (защиты атрибутов). Атрибуты можно удалять и добавлять динамически в любой момент жизни объекта.

> **🟢 Новое понятие:** **`self`** — неявный первый параметр любого метода экземпляра класса, представляющий ссылку на сам объект, вызвавший этот метод.
> **🟢 Новое понятие:** **Инкапсуляция** — механизм сокрытия внутреннего состояния объекта (в Python реализована слабо, на уровне соглашений, а не жестких ограничений языка).
