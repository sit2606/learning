### 3. Черный ящик и спецификации
При использовании уже написанной функции (например, `findTime`) мы рассматриваем ее как абстракцию.
* **Черный ящик** (или **непрозрачный ящик**) — это модель, внутреннее устройство которой нам неизвестно, но мы точно знаем, какие данные подаются на вход и какой результат возвращается на выход.
* **Спецификация** — формальное описание того, как код *должен* работать. Без спецификации невозможно отличить баг (ошибку) от фичи (особенности), так как не с чем сравнивать фактическое поведение кода.
  * **Предусловие** — условия, которые должны выполняться перед запуском кода (например, формат и наличие входных данных).
* **Постусловие** — условия, которые гарантируются после выполнения кода (например, формат возвращаемого значения).

### 4. Тип данных `None` и `NoneType`
Если функция в Python не содержит оператора `return` или он пустой, она возвращает специальное значение.
* **`None`** — единственный объект типа **`NoneType`**, который означает отсутствие значения.
* При попытке форматированного вывода (например, `:.1f`) для переменной со значением `None` возникнет ошибка. Необходимо явно проверять: `if time1 is None: ...`

### 5. Модули и импорт в Python
Копирование и вставка кода (Copy-Paste) — плохая практика, так как приводит к расхождению копий и сложностям при исправлении ошибок. Код нужно переиспользовать.
* **Модуль** — это обычный файл с расширением `.py`.
* **Импорт** — механизм подключения кода из одного модуля в другой.
  * *Вариант 1:* `import lifeguard_final`. Обращение к функциям через точку: `lifeguard_final.findTime()`.
  * *Вариант 2 (с псевдонимом):* `import lifeguard_final as lgf`. Позволяет использовать короткое имя `lgf.findTime()`.
  * *Вариант 3 (импорт конкретных имен):* `from lifeguard_final import findTime, temp`. Имена добавляются в текущую область видимости, и префикс модуля не нужен.
  * *Вариант 4 (импорт всего):* `from lifeguard_final import *`. **Не рекомендуется!** Приводит к загрязнению пространства имен, конфликтам переменных и затрудняет анализ кода (непонятно, откуда взялась переменная).

### 6. Специальная переменная `__name__` и блок `__main__`
При импорте модуля выполняется весь его код. Чтобы отладочный код или тесты выполнялись только при прямом запуске файла, а не при его импорте, используется проверка:
```python
if __name__ == '__main__':
    # Код, который выполнится только при прямом запуске этого файла
```
* Если модуль импортируется, его `__name__` равен имени файла (например, `lifeguard_final`).
* Если модуль запускается напрямую, его `__name__` автоматически становится равным **`'__main__'`**.

### 7. Test-Driven Development (TDD) и тестирование
* **Test-Driven Development (TDD)** (Разработка, управляемая тестами) — методология, при которой тесты пишутся *до* написания основного кода.
  * *Преимущества:* Фокус на том, что код *должен* делать, а не на том, как он реализован сейчас; предотвращает перенос ошибок из кода в тесты; дает четкие критерии завершения работы (когда все тесты проходят).
* **Сравнение чисел с плавающей точкой:** Из-за погрешностей вычислений строгое равенство (`==`) использовать опасно.
  * **Эпсилон-окрестность** — подход, при котором два числа считаются равными, если модуль их разницы меньше заданного малого числа (эпсилона). В Python: `abs(actual - expected) <= 0.1`.
* Для избежания дублирования кода в тестах используется рефакторинг: выделение повторяющихся действий в цикл и использование списков (в том числе двумерных) для хранения наборов входных и ожидаемых данных.

### 8. Решение задачи оптимизации (Задание 3)
Задача: найти оптимальный угол, при котором время минимально.
1. **Численное моделирование:** перебор значений угла в цикле и поиск минимума.
2. **Цикл `for` с `range`:** удобен для целочисленного шага (например, от 0 до 90). Для шага 0.1 можно использовать хитрость: перебирать целые числа от 0 до 900 и делить их на 10 внутри цикла, либо использовать вложенный цикл.
3. **Цикл `while`** — альтернативный способ, выполняющийся, пока истинно заданное условие. Позволяет легко делать дробный шаг (например, `theta += 0.1`), но требует ручного изменения переменной, чтобы избежать **бесконечного цикла**.
4. Для нахождения минимума можно использовать встроенную функцию `min()` для списка накопленных значений.
5. **Параллельные структуры данных** — использование двух и более списков, где элементы с одинаковыми индексами логически связаны (например, в одном списке хранятся времена, в другом под теми же индексами — соответствующие углы). Это позволяет найти индекс минимального времени и по нему извлечь нужный угол.
6. Весь код подбора оптимального значения следует оформить в отдельную функцию (например, `find_opt_time`), чтобы его можно было протестировать.

### 9. Именованные константы и «магические числа»
* **Именованные константы** — переменные, имена которых записаны ЗАГЛАВНЫМИ БУКВАМИ (например, `FEET_IN_YARD = 3`). В Python интерпретатор не запрещает их менять, но это *соглашение*: программист дает сигнал, что это значение не должно изменяться.
* **Магические числа** — необъяснимые числовые литералы в коде (например, `26`, `3`, `60`). Их использование — плохая практика.
  * *Проблема:* при глобальной замене (например, с 26 на 33 при переходе на кириллицу) можно сломать другие части кода, где число 26 имело иной смысл.
  * *Исторический пример:* **Проблема 2000 года (Y2K)**. Программисты экономили память и хранили год двумя цифрами, считая век (19) неизменной константой. Это привело к глобальным сбоям при наступлении 2000 года.
  * *Вывод:* Всегда заменяйте магические числа на именованные константы с понятными названиями.
