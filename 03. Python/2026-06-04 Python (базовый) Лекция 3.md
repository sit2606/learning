### 2. Олимпиадное программирование и платформа Codeforces
*   **Codeforces** – российская платформа для тренировок и соревнований, созданная Михаилом Мирзаяновым (поддерживается ИТМО).
*   **ICPC** (International Collegiate Programming Contest) – международная некоммерческая организация, проводящая студенческие олимпиады по программированию. Система отбора: региональный этап → континентальный этап → мировой финал.
*   **Рейтинг на Codeforces:** имеет большое значение. >1000 – неплохо, >1500 – очень круто, у лидеров >3000.
*   **Дивизионы:** новичкам рекомендуется начинать с Дивизиона 4 или 3 (Дивизион 1 – самый сложный).
*   **Ограничения:** обычно 1 секунда времени и 256 МБ памяти. Одинаковы для всех языков, поэтому на реальных олимпиадах часто предпочитают C++ (он быстрее), но для учебных задач Python подходит.
*   **Категории алгоритмов:** задачи часто относятся к типовым подходам, например, **Brute force (полный перебор)** или **Жадные алгоритмы (greedy)**.
*   *Рекомендованная литература:* Книга «Алгоритмы: построение и анализ» (авторы, в т.ч. Клиффорд Штайн). Фундаментальный труд, применимый к любому языку программирования.

### 3. Основы работы программ: от машинного кода до интерпретатора
*   Внутри компьютера все данные и инструкции представлены в виде **двоичного кода** (битов). Для компактности люди используют **шестнадцатеричную** запись.
*   **Ассемблер** – язык низкого уровня, использующий мнемоники (ADD, MOV, JMP) вместо машинных кодов. Он привязан к конкретной архитектуре процессора (x86, ARM и т.д.).
*   **Транслятор** – программа, преобразующая исходный код в машинный. Бывает двух основных видов:
    1.  **Компилятор:** переводит весь исходный код в машинный (создает **объектный модуль**), затем **компоновщик (линковщик)** собирает их в единый исполняемый файл (например, `.exe` или `ELF`). Код выполняется быстро, но привязан к ОС и архитектуре.
    2.  **Интерпретатор:** выполняет код построчно или компилирует его «на лету» внутри себя (как Python). Работает медленнее нативного кода, но обеспечивает кроссплатформенность.
*   **Жизненный цикл разработки ПО:** Проектирование → Написание исходного кода → Компиляция/Запуск → **Тестирование** → Исправление ошибок (циклический процесс).

### 4. Циклы в Python
*   Код, написанный вне функций, выполняется в **глобальной области видимости (global scope)** линейно.
*   **Цикл `for`** позволяет выполнять блок кода (**тело цикла**) многократно. Одно выполнение тела цикла называется **итерацией**.
*   Функция **`range()`** генерирует диапазон чисел:
    *   `range(n)`: от 0 до n-1 (шаг 1).
    *   `range(start, stop)`: от start до stop-1 (шаг 1).
    *   `range(start, stop, step)`: от start до stop-1 с указанным шагом (step может быть отрицательным).
*   Оператор **`pass`** – специальная заглушка («пустая» команда), используется, когда синтаксис требует наличия блока кода, но логика еще не реализована.

### 5. Работа со списками (массивами) в Python
*   В Python аналогом массива является **список (List)** – упорядоченная (но не обязательно отсортированная) структура данных.
*   Метод строки **`split()`** разбивает строку на элементы списка (по умолчанию по пробелам).
*   Индексация в списках начинается с **0**.
*   Функция **`len()`** возвращает количество элементов в списке.
*   Метод **`append()`** добавляет новый элемент в конец списка.
*   Списки в Python **изменяемы** (можно менять элементы по индексу). В отличие от них, **кортежи (tuples)** – это неизменяемые списки.
*   Преобразование типа: `int()` применяется к отдельным элементам, а не ко всему списку сразу (для массового преобразования нужен цикл или List Comprehension, о котором будет рассказано позже).

### 6. Рефакторинг и стандарты именования
*   **Рефакторинг** – это улучшение структуры, читаемости и дизайна кода *без изменения его внешней функциональности*.
*   После любого рефакторинга необходимо проводить **регрессионное тестирование**, чтобы убедиться, что ничего не сломалось.
*   *Правило именования:* имена переменных должны быть описательными и содержать не менее 3 символов (избегать `a`, `b`, `x`, `k1`).

### 7. Функции и области видимости
*   Функция определяется ключевым словом **`def`**, имеет имя, параметры в круглых скобках и завершается двоеточием.
*   **`return`** – оператор, возвращающий результат вычислений из функции в точку вызова.
*   **Чистая функция (pure function)** – функция, которая не имеет побочных эффектов (не изменяет внешние данные, а только вычисляет и возвращает значение на основе входных параметров).
*   **Процедура** – подпрограмма, которая не возвращает значения (`return` отсутствует или возвращает `None`), но имеет побочные эффекты (например, изменяет переданный список).
*   **Область видимости:** переменные, созданные внутри функции (**локальные переменные**), не видны снаружи. Глобальная область не имеет доступа к локальным переменным функций.
*   Оператор **`del`** используется для явного удаления переменной из памяти.

### 8. Тестирование кода
*   Тестирование через пользовательский ввод неудобно для сложных программ.
*   **Модульное тестирование (Unit testing)** – подход, при котором тестируется отдельная изолированная часть кода (например, одна функция). Сравниваются **expected** (ожидаемый) и **actual** (фактический) результаты.
*   *Золотое правило тестирования:* Тесты никогда не удаляются, они только добавляются. Это обеспечивает надежность при **регрессионном тестировании**.
*   **Doctest** – встроенный в Python модуль для тестирования. Тесты пишутся прямо в строке документации (docstring) функции в формате интерактивной сессии (начинаются с `>>>`). Запускается через `import doctest` и `doctest.testmod()`.
