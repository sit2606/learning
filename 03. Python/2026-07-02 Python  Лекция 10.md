## 1. Введение и работа с состоянием объекта
На предыдущей лекции был создан первый класс, определены методы и атрибуты. 
*   **Состояние объекта** — это набор значений атрибутов, характерных для конкретного экземпляра.
*   Методы предназначены для изменения состояния объекта.

**Работа с глобальными переменными из методов:**
Если метод должен изменять глобальную переменную, необходимо использовать ключевое слово `global`.
```python
cnt = 10
def incAge(self):
    global cnt # Сообщаем интерпретатору, что меняем глобальную, а не создаем локальную
    cnt += 1
```
> ⚠️ **Важно:** Использовать глобальные переменные — плохая практика. Они могут быть изменены в любом месте кода, что усложняет поиск ошибок. Локальные переменные затеняют глобальные. Глобальные переменные следует избегать или тщательно документировать.

## 2. Строковое представление объектов и наследование
По умолчанию при выводе объекта (`print(person)`) мы получаем недружелюбную строку с указанием модуля, класса и hex-значения `id`.

Чтобы сделать вывод красивым, можно написать метод, возвращающий строку (например, `pair()`), но это требует явного вызова. В Python есть механизм неявного вызова строкового представления.

> 🟢 **[Новое понятие: Наследование от `object`]**
> В Python, если при объявлении класса не указан предок, он **по умолчанию наследуется от класса `object`**. 

Класс `object` содержит базовый метод для представления объекта в виде строки. Мы можем **переопределить** его в своем классе.

> 🟢 **[Новое понятие: Магические методы (Dunder methods)]**
> Методы с именами, начинающимися и заканчивающимися на двойное подчеркивание (например, `__str__`), называются **магическими** или **dunder-методами** (от *double underline*).

Переопределив `__str__`, мы заставляем функцию `print` и другие контексты, требующие строку, использовать нашу логику:
```python
def __str__(self):
    return f"Person object with name {self.name} and age {self.age}"
```
*Примечание:* Переопределение метода в классе-потомке не затрагивает класс-предок (`object`). Потомок получает *копию* навыка предка и может его изменить.

## 3. Инициализация объектов
Чтобы не задавать атрибуты вручную после создания объекта, используется специальный метод, вызываемый автоматически при создании экземпляра.

> 🟢 **[Новое понятие: Инициализатор (`__init__`)]**
> Метод `__init__` вызывается сразу после создания объекта для настройки его атрибутов. 
> *Строго говоря, это не конструктор (конструктор — это `__new__`), а именно инициализатор, но в литературе его часто называют конструктором.*

```python
def __init__(self, objName="", objAge=0):
    self.name = objName
    self.age = objAge
```
*   Использование **параметров по умолчанию** позволяет не ломать старый код, который создавал объекты без аргументов.
*   Если добавить обязательные параметры, все старые вызовы `Person()` сломаются с ошибкой `missing positional arguments`.

## 4. Атрибуты класса и атрибуты экземпляра
В Python переменная с одним именем может существовать в четырех разных областях:
1.  **Глобальная переменная** (`global var`)
2.  **Локальная переменная** (внутри функции/метода)
3.  **Атрибут экземпляра** (`self.var`) — уникален для каждого объекта.
4.  **Атрибут класса** (`ClassName.var`) — существует в единственном экземпляре на весь класс и разделяется между всеми объектами.

**Правила разрешения имен (Resolution Order):**
*   Если мы обращаемся к `self.enn`, но у экземпляра нет такого атрибута, Python **автоматически ищет его на уровне класса**.
*   Если атрибут класса найден, он используется как значение по умолчанию.
*   Если мы присвоим `self.enn = 77`, мы создадим **атрибут экземпляра**, который "затенит" атрибут класса для данного конкретного объекта. Изменения атрибута класса больше не будут влиять на этот объект.

**Пример со счетчиком объектов:**
Счетчик созданных объектов (`cnt`) логично делать **атрибутом класса**, так как он общий для всех экземпляров.
```python
class Person:
    count = 0 # Атрибут класса
    def __init__(self):
        Person.count += 1
```

## 5. Статические методы
Если методу для работы не нужен конкретный экземпляр объекта (не нужен `self`), а он работает только с атрибутами класса, он называется статическим.

> 🟢 **[Новое понятие: Статический метод]**
> Метод, который не принимает `self` в качестве первого параметра. Вызывается **от имени класса**, а не от имени экземпляра.

```python
def getCount():
    return Person.count

# Вызов:
print(Person.getCount()) 
```
*Ошибка:* Если вызвать `Person().getCount()`, Python попытается передать ссылку на объект как первый аргумент, что вызовет ошибку несоответствия количества аргументов.

## 6. Наследование и переопределение методов
> 🟢 **[Новое понятие: Суперкласс и Подкласс]**
> **Суперкласс** (родитель, предок) — класс, от которого наследуются свойства. **Подкласс** (потомок) — класс, который наследует.

**Правила проектирования:**
*   Предок всегда проще и/general.
*   Потомок специализирован и содержит всё от предка + что-то новое.
*   Не рекомендуется отказываться от наследства (хотя в Python это возможно через `del`).

**Вызов инициализатора предка:**
В Python инициализатор предка **не вызывается автоматически**. Его нужно вызывать явно в `__init__` потомка, иначе атрибуты предка (например, `name` и `age`) не создадутся, и методы предка, обращающиеся к ним, вызовут ошибку.

```python
class Student(Person):
    def __init__(self, objGroup, objName="", objAge=0):
        super().__init__(objName, objAge) # Вызов инициализатора предка
        self.group = objGroup
```
*Функция `super()` возвращает ссылку на объект класса-предка и позволяет элегантно вызывать его методы без жесткого привязывания к имени класса.*

> 🟢 **[Новое понятие: Принцип подстановки Лисков (LSP)]**
> При переопределении методов нельзя радикально менять контракт (спецификацию) метода. Например, если предок возвращает строку, потомок тоже должен возвращать строку, а не просто печатать её на экран.

## 7. Жизненный цикл объекта и деструктор
Объекты создаются при вызове класса. Память освобождается, когда на объект **не остается ссылок**. Этим занимается **Сборщик мусора (Garbage Collector)**.

> 🟢 **[Новое понятие: Деструктор (`__del__`)]**
> Магический метод `__del__`, который вызывается при уничтожении объекта сборщиком мусора.

*   **Недетерминированность:** Нельзя точно предсказать, *когда именно* сработает `__del__`. Память может освободиться сразу после потери ссылки, а может только при завершении программы.
*   Деструктор предка **не вызывается автоматически** при уничтожении объекта потомка. Его нужно вызывать явно через `super().__del__()`.
*   В `__del__` удобно уменьшать счетчик объектов класса.

## 8. Магические методы (Dunder methods) и операции
С помощью dunder-методов можно реализовать поддержку стандартных операторов (`+`, `-`, `*`, `/`, `[]` и т.д.) для собственных классов.

**Основные группы методов:**
*   **Создание/Удаление:** `__new__` (истинный конструктор), `__init__`, `__del__`.
*   **Числовые/Арифметические:** `__add__` (`+`), `__sub__` (`-`), `__mul__` (`*`), `__truediv__` (`/`), `__mod__` (`%`), `__abs__`, `__neg__` (унарный минус).
*   **Строковые:** `__str__` (для `print`), `__repr__`.
*   **Исследование:** `__dir__` (используется встроенной функцией `dir()` для показа всех атрибутов и методов объекта).

*Пример реализации сложения:*
```python
def __add__(self, other):
    # self - левый операнд, other - правый
    return Person(self.name + other.name, 0) # "Ребенок" с именем из имен родителей
```

## 9. Сравнение объектов
По умолчанию операторы `==` и `is` для разных объектов с одинаковым содержимым вернут `False`.
*   `is` — сравнивает **ссылки** (указывают ли переменные на одну и ту же ячейку памяти).
*   `==` — должно сравнивать **состояние** (содержимое), но для кастомных классов это нужно настраивать.

> 🟢 **[Новое понятие: Метод `__eq__`]**
> Магический метод для переопределения логики сравнения на равенство (`==`).

```python
def __eq__(self, other):
    return self.name == other.name and self.age == other.age
```
*Разработчик сам решает, какие атрибуты делают два объекта "равными" по смыслу.*

## 10. Класс как объект и идентификатор
Имя класса в Python — это просто **идентификатор (переменная)**, указывающая на объект класса.
*   Классу можно присвоить новое имя (алиас): `AnyPerson = Person`. Оба имени будут указывать на один класс.
*   Класс можно переопределить (например, `Person = 10`), после чего создание экземпляров станет невозможно.
*   **Локальные классы:** Определение класса можно поместить внутрь функции или блока `if`.

## 11. Практические примеры: Point и Stack
**Пример 1: Класс Point (Точка)**
*   Атрибуты `x`, `y`.
*   Метод `distanceFromOrigin` (использует `math.hypot`).
*   Переопределены `__eq__` и `__str__`.

> ⚠️ **Ошибка "Мертвый код" (Dead Code) при именовании:**
> Если в `__init__` написать `name = name` вместо `self.name = name`, ошибки не будет. Python просто присвоит локальной переменной её же значение. Атрибут объекта не создастся.
> *Совет:* Называйте параметры иначе, чем атрибуты (например, `objName` или `nName`), чтобы визуально отличать их и не забывать `self`.

**Пример 2: Класс Stack (Стек)**
> 🟢 **[Новое понятие: Стек (LIFO)]**
> Структура данных **Last In, First Out** (Последним вошел, первым вышел). Аналогия со стопкой тарелок. Основные операции: `push` (положить) и `pop` (извлечь).
> *(Альтернатива: Очередь FIFO - First In, First Out).*

*   Внутреннее хранение: список (`_stack`).
*   Методы: `push`, `pop`, `top` (подсмотреть без извлечения).
*   Переопределен `__len__` (позволяет использовать встроенную функцию `len()` к объекту стека).

## 12. Рефлексия и управление атрибутами
> 🟢 **[Новое понятие: Рефлексия]**
> Возможность исследования объекта средствами его собственных атрибутов.

**Словарь `__dict__`:**
*   У каждого экземпляра есть `__dict__` — словарь, содержащий все его атрибуты.
*   Через `__dict__` можно читать, добавлять и удалять атрибуты напрямую (`obj.__dict__['new_attr'] = 10`).
*   У класса тоже есть `__dict__`, но он отображается как `mappingproxy` (только для чтения).

**Встроенные функции для работы с атрибутами:**
> 🟢 **[Новое понятие: hasattr, getattr, setattr]**
> Более высокоуровневый и безопасный интерфейс для работы с атрибутами, чем прямой доступ к `__dict__`.
*   `hasattr(obj, 'name')` — проверяет наличие атрибута.
*   `getattr(obj, 'name')` — возвращает значение.
*   `setattr(obj, 'name', 'Peter')` — устанавливает/изменяет атрибут.

## 13. Перегрузка функций в Python
> 🟢 **[Новое понятие: Перегрузка функций (Overloading)]**
> Возможность создавать несколько функций с **одним именем**, но **разным количеством или типами параметров**.

**В Python перегрузка функций НЕ ПОДДЕРЖИВАЕТСЯ.**
Позднее определение функции с тем же именем просто перетирает предыдущее (так как имя функции — это просто ссылка на объект-функцию).

**Альтернативы в Python:**
1.  **Параметры по умолчанию:** `def f(a, b, c=1):`
2.  **Произвольное количество аргументов (`*args`):**
    ```python
    def multiply(*args):
        res = 1
        for i in args: res *= i
        return res
    ```
    *(Аргументы автоматически упаковываются в кортеж).*
3.  Использование готовых функций, например, `math.prod(iterable)`.

## 14. Инкапсуляция и защита данных
> 🟢 **[Новое понятие: Инкапсуляция]**
> Один из трех китов ООП (наряду с наследованием и полиморфизмом). Механизм защиты внутреннего состояния объекта от внешнего мира. Разделение на **публичный интерфейс** и **приватную (внутреннюю) реализацию**.
> *Аналогия из жизни:* Динамическое ценообразование на маркетплейсах. Покупатель скрывает свою максимальную цену (инкапсулирует), а алгоритмы маркетплейса пытаются её угадать.

**Средства инкапсуляции в Python:**

1.  **Соглашение об именовании (Name Mangling):**
    *   Если атрибут начинается с двух подчеркиваний (`__count`), Python считает его приватным.
    *   При попытке обратиться `obj.__count` выдаст `AttributeError`.
    *   *Но это защита "от честных людей":* Python просто меняет имя атрибута на `_ClassName__count`. Через `__dict__` или прямое обращение к `_B2__count` доступ всё равно можно получить.
2.  **Перехват присваивания (`__setattr__`):**
    *   Можно переопределить `__setattr__`, чтобы запретить создание новых атрибутов или валидировать значения.
    *   *Обход:* Опять же, через прямой доступ к `__dict__` защиту можно обойти.
3.  **Свойства (Getters и Setters):**
    > 🟢 **[Новое понятие: Декораторы `@property` и `@<attr>.setter`]**
    > Позволяют превратить метод в атрибут. Дают полный контроль над чтением и записью значения, позволяя проводить валидацию данных.
    ```python
    @property
    def age(self): return self.__age
    
    @age.setter
    def age(self, value):
        if 1 <= value <= 99: self.__age = value
        else: print("Недопустимый возраст")
    ```
