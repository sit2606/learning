**Повторение предыдущей лекции:**

## 2. Проблема установки баз данных

**Проблема:**
- Приложение работает с базой данных (например, PostgreSQL)
- Инсталлер может спросить у пользователя расположение PostgreSQL, имя пользователя, пароль
- Через утилиту `psql` можно загрузить базу данных из дампа
- **НО:** инсталлер НЕ может установить полноценную PostgreSQL
- Установка PostgreSQL плохо поддается автоматизации
- Пользователь может не захотеть устанавливать тяжелую СУБД локально

**Решение:**
- Упаковать PostgreSQL вместе с приложением
- **Контейнеризация** — способ подготовки слоев софта для предоставления пользователю

## 3. Виртуализация

> [!info] **Виртуализация** — процесс совместного доступа к ресурсам компьютерной системы таким образом, что создается впечатление существования нескольких независимых ресурсов.

**Ключевые моменты:**
- Операционная система уже обеспечивает разделение ресурсов (процессор, память, диски) между процессами
- Процессы изолированы друг от друга по соображениям безопасности
- Виртуализация позволяет **нескольким операционным системам работать на одном компьютере одновременно**

**Исторический контекст:**
- Раньше использовалась мультизагрузка (выбор ОС при включении компьютера)
- Только одна ОС могла быть активной в каждый момент времени
- Виртуализация устранила этот недостаток

**Терминология:**
- **Хост-система (Host)** — основная операционная система, установленная традиционным способом
- **Гостевая система (Guest)** — виртуальная операционная система, работающая в рамках хоста

**Примеры ПО для виртуализации:**
- Oracle VirtualBox
- VMware
- WSL (Windows Subsystem for Linux) — более тесная интеграция с Windows

**Процесс создания виртуальной машины:**
1. Создать новую виртуальную машину
2. Указать образ диска (дистрибутив) с ОС
3. Виртуальная машина — это виртуальный диск + ресурсы (процессор, память)
4. На виртуальном диске устанавливается полноценная копия гостевой ОС

**Ограничения:**
- Гостевая система — это полноценная ОС (ядро, драйверы, системные программы)
- Размер: от 1 ГБ до десятков ГБ
- Требует аппаратной поддержки виртуализации (настройки BIOS: SVM для AMD, VT-x для Intel)
- Каждая ВМ требует минимум одно ядро процессора и выделенную память
- Ресурсы между ВМ не объединяются

**Лицензионные ограничения:**
- macOS по лицензии Apple можно запускать только на оборудовании Apple
- Получить ISO-образ macOS крайне сложно

## 4. Grid Computing (Грид-вычисления)

> [!info] **Grid Computing** — способ организации параллельных вычислений, при котором задача распределяется по нескольким или многочисленным компьютерам.

**Концепция:**
- Вместо покупки дорогого процессора со 128 ядрами можно использовать много дешевых 8-16 ядерных компьютеров
- Разделить задачу между компьютерами
- Каждый компьютер решает свою часть задачи
- Результаты собираются в общий результат

**Пример: MapReduce**
- Раздать задачи всем компьютерам
- Дождаться выполнения
- Собрать результаты

**Исторические проекты:**
- **SETI@home** (Search for Extraterrestrial Intelligence) — поиск внеземного разума
  - Обработка данных с радиотелескопов
  - Поиск искусственных радиосигналов в космическом шуме
  - Проект существовал до 2000-х годов
  - Технически успешен, но результатов не дал
- **Folding@home** — еще один популярный проект рубежа веков

**Современное применение:**
- Майнинг криптовалют
- Вредоносные программы, использующие ресурсы компьютера без ведома пользователя

## 5. Облачные вычисления

> [!info] **Облачные вычисления** — централизованная модель, при которой вычислительные ресурсы концентрируются в дата-центрах и выдаются пользователям дозировано.

**Принцип работы:**
- Компьютеры плотно размещаются в дата-центрах (часто подземных)
- Стойки с серверами занимают сотни тысяч квадратных метров
- Ресурсы объединяются и выдаются с высокой точностью

**Преимущества:**
- Можно арендовать не физический сервер, а ресурс (процессоры, память, диски)
- Динамическое изменение ресурсов без остановки приложения
- Высокая отказоустойчивость (мгновенное переключение при сбое оборудования)
- Бесшовность (пользователь не знает физического расположения ресурсов)

**Примеры облачных платформ:**
- Яндекс.Облако
- СберКлауд
- AWS (Amazon Web Services)
- Microsoft Azure
- Oracle Cloud
- NASA

**Частные облака:**
- Компании создают собственные облачные инфраструктуры по соображениям безопасности
- Используют облачные технологии, но не отдают данные третьим лицам

**Проблема с памятью (2026 год):**
- Цены на память (DDR5) взлетели почти год назад
- Причина: спрос со стороны ИИ-компаний для тренировки нейронных сетей
- В мире всего 2 компании производят память
- Загружены заказами больше чем на год вперед

## 6. Контейнеризация и Docker

> [!info] **Контейнеризация** — технология упаковки приложения со всеми его зависимостями в легковесный изолированный контейнер, который работает поверх общей операционной системы.

> [!info] **Docker** — самое популярное ПО для контейнеризации, появившееся около 10-12 лет назад (2013-2014).

**Почему контейнеры лучше виртуальных машин:**
- Виртуальные машины слишком тяжеловесные (каждая содержит полную ОС)
- Для распространения одного приложения запускать целую ВМ — избыточно
- Контейнеры содержат только приложение и зависимости, без ОС
- Все контейнеры используют общее ядро ОС (Linux)

**Как работает Docker:**
- Внутри Docker работает Linux
- На Windows/macOS используется виртуализация (незаметно для пользователя)
- Docker Desktop использует WSL (Windows Subsystem for Linux) в современных версиях
- Контейнеры — это изолированные процессы
- Для хост-ОС это обычные нативные процессы

**История:**
- Технология контейнеров существовала с 90-х годов
- Docker сделал технологию удобной и доступной
- Взрывной рост популярности в конце 2013 года
- Наличие открытого стандартного API — ключ к успеху

**Преимущества Docker:**
- Инкапсуляция приложения (все в одном образе)
- Воспроизводимость (одинаковая работа везде)
- Простое развертывание в облаке (AWS, Azure, SberCloud и др.)
- Поддержка всеми основными платформами
- Управление множеством контейнеров (Kubernetes)

**Редакции Docker:**
- **Community Edition** — бесплатная, используется в курсе
- **Enterprise Edition** — платная, для корпоративных нужд

## 7. Docker Hub и репозитории

> [!info] **Docker Hub** — облачное хранилище для Docker-образов, аналог GitHub для кода.

**Регистрация:**
- Бесплатный план предоставляет место в облачном хранилище
- URL: `hub.docker.com`
- Публичные репозитории доступны всем

**Основные команды:**
- **`docker push`** — отправить обновленный образ в Docker Hub (аналог `git push`)
- **`docker pull`** — скачать образ из Docker Hub

**Структура URL репозитория:**
- `hub.docker.com/r/username/repository` — публичный вид
- `hub.docker.com/repositories/username` — вид владельца

**Безопасность:**
- Docker Hub — это хранилище, автоматической гарантии безопасности нет
- Образы могут содержать вредоносный код
- Нужно проявлять осмотрительность (как с GitHub)
- Docker Hub может удалять репозитории по жалобам

## 8. Образы и контейнеры

> [!info] **Образ (Image)** — статический файл, содержащий все необходимое для запуска приложения (код, библиотеки, конфигурация).

> [!info] **Контейнер (Container)** — запущенный образ, выполняющийся процесс в оперативной памяти.

**Аналогия:**
- Образ = файл программы на диске
- Контейнер = работающая программа

**Слоистая структура образов:**
- Образ состоит из слоев (как луковица)
- Слои скачиваются по отдельности
- Слои могут переиспользоваться между образами

**Основные команды Docker:**

```bash
docker --version          # Проверка версии Docker
docker ps                 # Список запущенных контейнеров
docker ps -a              # Список всех контейнеров (включая остановленные)
docker images             # Список локальных образов
docker run <image>        # Запустить контейнер из образа
docker pull <image>       # Скачать образ из репозитория
docker push <image>       # Отправить образ в репозиторий
```

**Параметры docker run:**
- `-p <host_port>:<container_port>` — маппинг портов
- `--name <name>` — задать имя контейнера

**Идентификация контейнеров:**
- **Container ID** — уникальный идентификатор (шестнадцатеричное число)
- **Имя** — более запоминающееся, генерируется случайно или задается вручную
- Уникальность гарантируется только в каждый момент времени

**Жизненный цикл контейнера:**
1. Образ скачивается (если его нет локально)
2. Контейнер создается из образа
3. Контейнер выполняется
4. Контейнер можно остановить, запустить заново, удалить
5. Образ остается локально даже после удаления контейнера

## 9. Архитектура Docker vs Виртуальные машины

**Архитектура виртуальных машин:**
```
┌─────────────────┐
│   Приложения    │
├─────────────────┤
│    Бинарники    │
│   Библиотеки    │
├─────────────────┤
│ Гостевая ОС     │ ← Каждая ВМ имеет свою ОС
├─────────────────┤
│   Гипервизор    │ ← Аппаратный
├─────────────────┤
│  Инфраструктура │
└─────────────────┘
```

**Архитектура Docker:**
```
┌─────────────────┐
│   Приложения    │
├─────────────────┤
│    Бинарники    │
│   Библиотеки    │ ← Только это включено в контейнер
├─────────────────┤
│     Docker      │ ← Общий для всех контейнеров
│     (Linux)     │
├─────────────────┤
│   Хост-ОС       │
├─────────────────┤
│  Инфраструктура │
└─────────────────┘
```

**Ключевые отличия:**
- ВМ: каждая имеет свою полную ОС (гигабайты)
- Контейнеры: используют общую ОС Docker (мегабайты)
- Контейнеры гораздо легковеснее
- Быстрее запускаются
- Меньше потребляют ресурсов

## 10. Практическая работа с Docker

**Установка Docker Desktop:**
- Скачать с официального сайта
- Убедиться, что "Engine running" (левый нижний угол)
- Проверить виртуализацию в BIOS (SVM для AMD, VT-x для Intel)
- Включить Hyper-V в Windows
- WSL может потребоваться в современных версиях

**Проверка работы:**
```bash
docker --version
docker ps
```

**Пример запуска:**
```bash
# Запуск с маппингом портов
docker run -p 8088:80 docker/getting-started

# Если образ не найден локально, он автоматически скачается
# Если образ есть локально, контейнер запустится сразу
```

**Проблемы и решения:**
- Порт занят другим сервисом → изменить маппинг портов
- Docker Desktop не запускается → проверить логи, виртуализацию, WSL
- "virtualization support not detected" → включить в BIOS

**Управление через Docker Desktop:**
- GUI для просмотра контейнеров и образов
- Кнопки Start/Stop/Delete
- Просмотр логов контейнера
- Inspect — информация о контейнере
- Exec — консоль внутри контейнера (Linux)

## 11. Сетевые концепции: IP-адресация

> [!info] **IP-адрес** — уникальный числовой идентификатор компьютера в сети, состоящий из четырех чисел (IPv4) в диапазоне 0-255.

**Примеры:**
- `192.168.2.14`
- `127.0.0.1` (localhost — локальная машина)
- `0.0.0.0` (адрес сервера/всех интерфейсов)

**Типы IP-адресов:**
- **Статические** — назначаются навсегда (платно, дефицит)
- **Динамические** — выдаются в аренду на время подключения
  - Аренда обычно несколько суток
  - Может меняться при переподключении

**IPv4 vs IPv6:**
- **IPv4** — 4 числа по байту (устаревает из-за нехватки адресов)
- **IPv6** — больше чисел в адресе (решение проблемы нехватки)

**Локальные сети:**
- Уникальность IP гарантируется только в рамках одной локальной сети
- В разных сетях могут быть пересекающиеся адреса
- Маршрутизация между сетями — отдельная сложная тема

## 12. DNS (Domain Name Service)

> [!info] **DNS** — служба доменных имен, которая преобразует человекочитаемые имена в IP-адреса.

**Принцип работы:**
- Доменное имя (например, `kuzm.soft.com`) → IP-адрес (`151.80.30.88`)
- Обратное преобразование (IP → имя) не всегда возможно
- DNS маскирует проблему динамических IP-адресов

**Зачем нужен DNS:**
- Людям легче запоминать имена, чем цифры
- Один домен может указывать на меняющиеся IP-адреса
- Всегда возвращает актуальный IP-адрес

## 13. Порты

> [!info] **Порт** — числовой идентификатор (0-65535) конкретного процесса на компьютере, используемый для сетевой адресации.

**Проблема с PID:**
- PID — внутренний номер процесса, меняется при каждом запуске
- Удаленный компьютер не может узнать PID нужного процесса
- Имена программ не уникальны (может быть несколько экземпляров)

**Решение — порты:**
- Фиксированный номер для определенного приложения
- Приложение "захватывает" порт при запуске
- ОС ведет таблицу соответствия: Порт → PID
- Порт — публичная информация

**Правила:**
- Один порт может слушать только один процесс
- Один процесс может слушать несколько портов
- Если порт никто не слушает — пакеты отбрасываются
- Порт должен быть свободен при запуске приложения

**Традиционные порты:**
- Порт 13 — служба времени
- Порт 80 — HTTP (веб-серверы)
- Порт 443 — HTTPS
- Порт 3306 — MySQL
- Порт 5432 — PostgreSQL

**Определение занятых портов (Windows):**
```bash
# Под администратором
netstat -a -b        # Показать процесс по имени
netstat -ano         # Показать PID процесса
```

**Статусы подключений:**
- **Listening** — порт прослушивается, ожидает подключения
- **Established** — активное подключение установлено

**Конфигурация портов:**
- Желательно делать порт настраиваемым (через .env файл)
- Предусматривать значение по умолчанию
- Обрабатывать исключения при занятом порте

## 14. Сокеты и клиент-серверная архитектура

> [!info] **Сокет** — программный интерфейс (объект) для обмена данными между приложениями через сеть.

**Клиент-серверная модель:**
- **Сервер** — пассивная сторона, слушает порт, ожидает подключения
- **Клиент** — активная сторона, инициирует подключение

**Процесс установления соединения:**
1. Сервер запускается и слушает порт
2. Клиент отправляет запрос на подключение (IP + порт сервера)
3. Сервер принимает или отклоняет подключение
4. Устанавливается канал связи "точка-точка"
5. Стороны обмениваются данными по протоколу
6. Подключение закрывается

**Несимметричность:**
- Одна сторона всегда делает первый шаг (клиент)
- Сервер может отклонить подключение
- Сервер играет роль ведомого после установления соединения

**Подключения "точка-точка":**
- Только две стороны могут обмениваться
- Подключение эксклюзивно (третья сторона не может подключиться)
- Групповой обмен реализуется через множественные точка-точка соединения

## 15. Протоколы TCP и UDP

> [!info] **TCP (Transmission Control Protocol)** — протокол с гарантией доставки, нумерацией пакетов и автоматической пересылкой потерянных пакетов.

> [!info] **UDP (User Datagram Protocol)** — протокол без подтверждения, допускает потерю пакетов, работает быстрее.

**TCP:**
- Все пакеты нумеруются
- Гарантируется порядок доставки
- Потерянные пакеты пересылаются
- Подходит для: бухгалтерских данных, файлов, веб-страниц
- Медленнее из-за проверок

**UDP:**
- Нет гарантии доставки
- Пакеты могут приходить в другом порядке
- Потерянные пакеты не пересылаются
- Подходит для: видео, аудио, онлайн-игр
- Быстрее за счет простоты

**Пример с видео:**
- TCP: потеря фрейма → остановка → пересылка → подвисание видео
- UDP: потеря фрейма → пропуск → плавное воспроизведение
- При высоком фреймрейте (100 fps) потеря одного фрейма незаметна

## 16. Инструменты для работы с сетью

**Telnet:**
- Древнейший инструмент (с 70-х годов, ~50 лет)
- Присутствует в Linux и Windows
- Работает посимвольно (не построчно)
- Backspace не работает как обычно
- В Windows может быть не установлен по умолчанию
  - Установка: "Turn Windows Features On and Off" → Telnet Client

**PuTTY:**
- Современный графический клиент
- Поддерживает Telnet, SSH и другие протоколы
- Удобнее Telnet
- Настройка: не закрывать окно после завершения подключения

**Пример подключения к серверу времени:**
```
Хост: time.nist.gov
Порт: 13
Протокол: Telnet
```
- Сервер отправляет текущее время (UTC)
- Сразу закрывает подключение
- Время основано на атомных часах
- Но из-за задержки сети время уже устаревшее на миллисекунды

## 17. Программирование сокетов в Python

**Модуль socket:**
- Встроенный модуль (не требует `pip install`)
- Нужно импортировать: `import socket`

**Пример клиента времени:**
```python
import socket

# Параметры подключения
server = 'time.nist.gov'
port = 13

# Создание сокета
s = socket.socket()

# Подключение
s.connect((server, port))

# Получение данных
msg = s.recv(1024)  # Блокирующая операция

# Закрытие сокета
s.close()

# Декодирование байтов в строку
print(type(msg))  # <class 'bytes'>
text = msg.decode('utf-8')
print(text)
```

**Важные моменты:**
- `recv()` возвращает массив байтов (bytes), не строку
- Нужно декодировать через `.decode('utf-8')` или другую кодировку
- Подключение блокирующее (код ждет ответа)
- Сервер может быть перегружен и отправить пустую строку

**Протокол общения:**
- Важно установить правила (протокол)
- Кто говорит первым?
- Что можно сказать?
- Как реагирует вторая сторона?
- Без протокола общение не получится
