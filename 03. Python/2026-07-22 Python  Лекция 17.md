## Введение в GUI-библиотеки

### Три основные библиотеки для GUI

В курсе рассматриваются **три библиотеки** для создания графических пользовательских интерфейсов:

1. **Tkinter** — исторически первая библиотека, поставляется вместе с Python
2. **PyQt / PySide** — порты библиотеки Qt (изначально для C++)
3. **WxPython** — базируется на WxWidgets, имитирует виджеты Windows XP

> **PyQt и PySide** — это порты одной и той же библиотеки Qt, различия минимальны. Для курса можно считать их идентичными.

Также упоминается **PyGTK** (порт стандартной Linux-библиотеки GTK), но в курсе не рассматривается.

**Популярность:**
- Наиболее популярные: **Tkinter** и **PyQt**
- **WxPython** встречается существенно реже в проектах

### Выбор библиотеки для заданий

- Для выполнения заданий **достаточно выбрать одну библиотеку**
- Не обязательно делать три версии GUI с каждой библиотекой
- Рекомендуется выбрать **две библиотеки** из трёх для более глубокого изучения
- Два задания с GUI:
  - Приложение **«Фермерские рынки»** (задание 7)
  - Игра **«Морской бой»** (задание 10, финальный проект)

## Консольные vs GUI-приложения

### Принцип работы консольных приложений (REPL)

До этого момента все приложения работали в **консольном режиме**:

- **REPL** (Read-Eval-Print Loop) — основной режим работы
- Приложение выводит сообщение через `print()`
- Пользователь реагирует, вводя команду
- Приложение выполняет команду, выводит результат
- Цикл повторяется

**Ключевая особенность:** использование `input()` — **блокирующая операция**. Пока пользователь не сделал ввод, код стоит и ждёт.

### Принцип работы GUI-приложений

**Desktop-приложения** (десктопные приложения) работают по другому принципу:

- Всегда отображается окно с элементами управления (**виджеты**)
- Пользователь может вмешиваться в любой момент:
  - Двигать полосу прокрутки
  - Вводить текст
  - Выбирать из выпадающего списка
- Если пользователь не вмешивается — приложение просто отображает последнее состояние
- Приложение **продолжает работать**, не блокируется

**Виджеты** — элементы управления: текстовые поля, переключатели, чекбоксы, выпадающие списки, кнопки, области вывода, полосы прокрутки и т.д.

### Многопоточность в GUI

> ⚡ **Новое понятие: Многопоточность** — механизм, лежащий в основе всех GUI-приложений, обеспечивающий параллельную обработку пользовательского ввода и отображение элементов интерфейса.

За любым GUI-приложением **стоит многопоточность**, хотя мы практически не будем вмешиваться в этот процесс на глубоком уровне.

## Desktop vs Web-приложения

### Эволюция приложений

**Историческая справка:**
- 30 лет назад: разница между **сайтами** и **приложениями** была чёткой
- Сейчас: разница **стёрта** — сайты могут делать всё то же, что и Desktop-приложения
- Появился термин **веб-приложение**
- Desktop-приложения потеряли значительную долю рынка

### Jupyter Notebooks как пример веб-приложения

**Jupyter Notebook** — пример приложения, которое:
- Работает в браузере
- Запускается локально (без внешнего сервера)
- Является **веб-приложением**, а не Desktop-приложением

### Гибридные решения (Electron)

> ⚡ **Новое понятие: Electron** — фреймворк, позволяющий упаковать веб-приложение в Desktop-версию. Внутри работает браузер, но выглядит как обычное десктопное приложение.

**Схема:** сначала создаётся веб-приложение, затем делается его «упаковка», которая запускается локально вне браузера (но браузер встроен в само приложение).

**Пример:** приложение **draw.io** (app.diagrams.net) — существует и как веб-версия, и как десктопное приложение (использует Electron).

**Преимущество:** очень дёшево — не нужно делать отдельно GUI-версию.

## Кроссплатформенность и Look and Feel

### Различия между ОС

Одно и то же приложение выглядит **по-разному** в разных операционных системах:

- **macOS** — кнопки закрытия/сворачивания красные/жёлтые/зелёные (слева)
- **Windows** — крестик, квадратик, подчёркивание (справа)
- **Linux** — наибольшая гибкость, есть понятие **look and feel**

> ⚡ **Новое понятие: Look and Feel** — как интерфейс выглядит и ощущается пользователем. В Linux можно переключать look and feel (Metal, Gnome и т.д.).

**Важно:** пользователи привыкли к стандартному виду кнопок управления окном в своей ОС. Нестандартный вид будет непривычен.

### Два пути реализации GUI-библиотек

**Путь 1: Делегирование отрисовки ОС**
- Библиотека просит операционную систему отрисовать виджеты стандартным способом
- **Результат:** приложение автоматически подстраивается под ОС, выглядит привычно
- **Преимущество:** элегантно, не требует особых усилий
- **Пример:** библиотеки, использующие системные виджеты

**Путь 2: Самостоятельная отрисовка**
- Библиотека сама отрисовывает все виджеты, независимо от ОС
- **Результат:** приложение выглядит **одинаково** на всех платформах
- **Преимущества:**
  - Унификация интерфейса
  - Легче отлаживать (look and feel фиксирован)
- **Недостатки:**
  - Может быть непривычно для пользователей
  - Как правило, **медленнее**, чем системная отрисовка

**К какому пути относятся рассматриваемые библиотеки:**
- **Tkinter** — старается отрисовывать самостоятельно (унификация)
- **PyQt** — большей частью прорисовывает самостоятельно (как Qt)
- **WxPython** — старается использовать виджеты, похожие на Windows XP

## Структура GUI-приложений

### Событийно-ориентированное программирование

> ⚡ **Новое понятие: Событийно-ориентированное программирование (Event-Driven Programming)** — способ построения кода, при котором приложение реагирует на **события** (асинхронные действия).

**События:**
- Действия пользователя (клавиатура, мышь)
- Сообщения от других процессов
- Данные по сети
- Таймеры и т.д.

**Синхронная vs Асинхронная модель:**
- **Синхронная (REPL):** приложение блокируется и ждёт ввода
- **Асинхронная (GUI):** приложение независимо от ввода, работает непрерывно

### Главный цикл приложения

> ⚡ **Новое понятие: Главный цикл приложения (Main Loop)** — бесконечный цикл (типа `while`), который запускается при старте и останавливается при завершении. На каждой итерации проверяет наличие событий.

**Важно:** главный цикл является **частью GUI-библиотеки**. Нам не нужно его писать — мы просто запускаем его.

### Обработчики событий (callbacks)

> ⚡ **Новое понятие: Функция-обработчик (Callback)** — функция обратного вызова, которая вызывается не нами, а **циклом обработки событий** при наступлении соответствующего события.

**Аналогия с консольным приложением (ZIP-приложение):**
```python
# REPL-цикл, который мы писали вручную:
while True:
    command = input()
    if command == "log":
        process_log()
    elif command == "zip":
        process_zip()
```

В GUI-приложениях:
- **Цикл уже написан** (часть библиотеки)
- **Диспетчеризация уже реализована**
- **Наша задача:** написать только **обработчики** и установить соответствие между событием и обработчиком

**Две главные задачи при создании GUI:**
1. Написать **обработчики событий**
2. Спроектировать **визуальный интерфейс**

## Tkinter — первая библиотека

### Особенности Tkinter

- **Поставляется вместе с Python** — не нужно устанавливать через `pip install`
- Легче распространять приложения
- **Исторически первая** GUI-библиотека для Python
- Близкий родственник пакета **Tcl/Tk** (стандарт для Linux)
- **Визуально не обновляется** с 90-х годов — «классический» вид
- **Кроссплатформенная** — одинаковый look and feel на разных платформах
- **Не требует** определения собственных классов (но поддерживает ООП-подход)
- Работает **медленнее** некоторых других библиотек

### Импорт и первое окно

**Импорт:**
```python
import tkinter as tk  # часто используют алиас tk
# или
from tkinter import *  # для больших проектов (хотя обычно не рекомендуется)
# или
from tkinter import messagebox  # импорт конкретных элементов
```

**Главное окно:**
```python
root = tk.Tk()  # объект класса Tk — главное окно
# часто называют root (корень дерева иерархии виджетов)
```

> Все остальные виджеты, контейнеры, окна — **дочерние** для объекта `Tk`. Формируется **иерархия**.

**Запуск главного цикла:**
```python
root.mainloop()  # запускает цикл обработки событий
```

**Простой пример с MessageBox:**
```python
from tkinter import messagebox
messagebox.showinfo("Information", "Welcome to ZPub")
```

## Виджеты Tkinter

### Основные виджеты

| Виджет | Класс | Описание |
|--------|-------|----------|
| **Кнопка** | `Button` | Поддерживает нажатие, может быть с фиксацией или без. Может содержать текст или изображение |
| **Флажок** | `Checkbutton` | Два состояния: включено/выключено |
| **Метка** | `Label` | Просто текст, поясняющий другие виджеты |
| **Однострочное поле** | `Entry` | Текстовое поле для ввода одной строки |
| **Многострочное поле** | `Text` | Многострочное текстовое поле с форматированием, вставкой рисунков |
| **Радиокнопка** | `Radiobutton` | Переключатель, зависимые варианты выбора (строго один или ни одного) |
| **Полоса прокрутки** | `Scrollbar` | Позиционирование при нехватке места |
| **Шкала** | `Scale` | Задание числовых значений бегунком |
| **Список** | `Listbox` | Выбор одного или нескольких элементов |
| **Холст** | `Canvas` | Рисование (примитивы, текст, изображения) |
| **Рамка** | `Frame` | Контейнер для организации виджетов |
| **Меню** | `Menu`, `Menubutton` | Организация меню (всплывающие, ниспадающие) |
| **Сообщение** | `Message` | Аналог Label, но с переносом длинных строк |
| **Окно верхнего уровня** | `Toplevel` | Отдельное окно, содержащее другие виджеты |

**Disable (запрещённый виджет):**
- Виджет присутствует, но серый и не реагирует на действия

**Радиокнопки:**
- Формируют **зависимую группу**
- Гарантируют: выбран **строго один** вариант или **ни одного**
- Невозможно выбрать два одновременно

### Модальные и немодальные окна

> ⚡ **Новое понятие: Модальное окно** — окно, требующее внимания. Пока оно открыто, **нельзя** работать с основным приложением. Приложение **блокируется**.

**Примеры:**
- `messagebox` — **модальное** окно
- «Свойства» в проводнике — **немодальное** окно
- «Preferences» в Spyder — **немодальное**
- «Open File» — **модальное** (сопровождается системным звуком, если попытаться кликнуть мимо)

**Важно:** пока модальное окно открыто, ввод не теряется — он **сохраняется** и обрабатывается после закрытия окна.

### Canvas (холст)

> ⚡ **Canvas** — виджет для рисования, актуален для задания **«Морской бой»**.

**Координатная система:**
- `(0, 0)` — **верхний левый угол**
- X увеличивается **вправо**
- Y увеличивается **вниз**
- Все координаты **неотрицательны**

**Параметры:**
- Размер внутри окна
- Цвет фона (`bg`)

**Методы рисования:**
- `create_line(x1, y1, x2, y2)` — отрезок линии
- `create_rectangle(...)` — прямоугольник (можно закрашенный)
- `create_oval(...)` — овал
- Вывод текста с указанием шрифта
- Рисование примитивов, попиксельное рисование

**Связь с заданием «Жизнь»:**
- Навыки из игры «Жизнь» (рисование поля, загрузка изображений) пригодятся для «Морского боя»
- Вместо Pillow используются средства Canvas

## Конфигурация виджетов

### Метод configure

```python
button.configure(text=current_time, command=buttonClicked)
```

**Параметр `command`:**
- Один из способов связать обработчик с событием
- Передаётся **имя функции** (без скобок!): `command=buttonClicked`
- Функция вызывается при активации виджета

### Доступ через квадратные скобки

Tkinter использует **синтаксис словаря** для доступа к свойствам:

```python
# Чтение значения
current_text = button["text"]

# Установка значения
button["text"] = new_time
```

Это **не настоящий словарь**, но классы виджетов переопределяют операцию индексирования для удобства.

### Метод cget

```python
bg_color = button.cget("bg")  # получить конфигурацию (background)
```

**Пример:** кнопка показывает свой предыдущий цвет фона, а при нажатии меняет фон на случайный цвет (шестнадцатеричный код).

### Удаление и скрытие виджетов

- `destroy()` — удаляет виджет **окончательно** как объект
- `grid_remove()` — **временно скрывает** виджет, сохраняя взаимное расположение остальных элементов
- `winfo_viewable()` — проверить, виден ли виджет (возвращает `True`/`False`)

## Менеджеры размещения в Tkinter

### Проблема абсолютного позиционирования

> ⚡ **Place** — менеджер размещения, использующий **абсолютные координаты** (X, Y).

**Почему Place не рекомендуется:**
- Интерфейс становится **негибким**
- Плохо переносит трансформации:
  - Увеличение шрифтов (для слабовидящих) → виджеты **наезжают друг на друга**
  - Изменение размеров окна
  - Разные разрешения экранов (4K vs 1280×1024)
- Виджеты «прибиты гвоздями» к координатам

**Вывод:** Place подходит только для **очень простых** интерфейсов или одноразовых демонстраций.

### Pack

> ⚡ **Pack** — менеджер размещения, использующий **алгоритм** взаимного расположения (не координаты).

**Принцип:** указываете, как виджеты расположены **относительно друг друга** (слева-справа, сверху-снизу), а pack сам пересчитывает координаты при трансформациях.

**Основные параметры:**
- `side` — сторона размещения: `"left"`, `"right"`, `"top"`, `"bottom"`
- `fill` — расширение: `"x"`, `"y"`, `"both"`, или нет
- `expand` — занять всё доступное пространство (`True`/`False`)
- `in_` — явное указание родительского виджета
- `padx`, `pady` — внешние отступы (поля от границы виджета)

**Комбинирование:**
- Практически никогда не удаётся оформить сложный интерфейс одним менеджером
- Используются **несколько фреймов** (контейнеров)
- К каждому контейнеру — свой менеджер размещения
- Pack и Grid можно **совмещать**

**Методы pack:**
- `pack_slaves()` — список дочерних виджетов (термин из 90-х, сейчас считается неполиткорректным)
- `pack_info()` — информация о конфигурации упаковки
- `pack_propagate()` — включить/отключить распространение геометрии
- `pack_forget()` — удалить виджет из размещения (аналог `grid_remove()`)

### Grid

> ⚡ **Grid** — менеджер размещения, использующий **невидимую таблицу** (строки и столбцы).

**Принцип:** указываете номер строки (`row`) и столбца (`column`) для каждого виджета.

**Основные параметры:**
- `row`, `column` — номер строки и столбца
- `rowspan`, `columnspan` — объединение строк/столбцов
- `padx`, `pady` — внешние отступы
- `ipadx`, `ipady` — **внутренние** отступы (расширяется сам виджет)
- `sticky` — «приклеивание» к стороне: `"n"`, `"s"`, `"e"`, `"w"` (или комбинации: `"nsew"`)
- `in_` — явное указание родителя

**Преимущества:**
- При увеличении шрифта — растёт размер ячеек, но **структура сохраняется**
- Взаимное расположение **не нарушается**
- Очень гибкий и удобный для сложных интерфейсов

**Методы grid:**
- `grid_slaves()` — список дочерних виджетов
- `grid_info()` — информация о размещении
- `grid_propagate()` — применить размещение на дочерние виджеты
- `grid_remove()` — удалить из упаковщика
- `grid_bbox()` — координаты bounding box в пикселях
- `grid_location(x, y)` — номер строки/столбца по координатам
- `grid_size()` — размер таблицы
- `grid_columnconfigure()`, `grid_rowconfigure()` — конфигурация строк/столбцов:
  - `minsize` — минимальный размер
  - `weight` — вес (определяет, насколько расширяется)
  - `uniform` — одинаковые настройки для группы
  - `pad` — отступ

**Пример выравнивания:**
```python
label.grid(row=0, column=0, sticky="w")  # выровнять влево (West)
label.grid(row=0, column=0, sticky="e")  # выровнять вправо (East)
```

### Place

**Параметры Place:**
- `x`, `y` — абсолютные координаты (**не рекомендуется**)
- `relx`, `rely` — относительные координаты (доли от 0 до 1)
- `width`, `height` — абсолютные размеры (**опасно** при изменении шрифта)
- `relwidth`, `relheight` — относительные размеры
- `anchor` — якорь (стороны света: `"n"`, `"ne"`, `"center"` и т.д.)

**Пример использования Place:**
```python
for i, lang in enumerate(languages):
    label = Label(text=lang, bg=colors[i])
    label.place(x=10, y=30 + i*30, width=120, height=25)
```

**Недостаток:** при увеличении шрифта текст **выходит за границы** фиксированной ширины/высоты.

### Wireframes и Mockups

> ⚡ **Wireframes / Mockups** — черновики интерфейса, наброски того, как будет выглядеть приложение.

**Важное правило:** любая разработка должна **начинаться с черновика**, а не с написания кода.

**Принципы создания черновиков:**
- Делайте черновики **дешёвыми** (не тратьте несколько часов)
- Черновик **может оказаться негодным** — его должно быть не жалко выкинуть
- Это поле для **экспериментов**
- Не старайтесь делать красиво и выверенно
- **Сохраняйте** черновики в репозитории

**Что должно быть отражено:**
- Все виджеты
- Логика игры/приложения
- Переходы между окнами
- Удобство использования
- Общая структура

## События в Tkinter

### Свойство command

**Для каких виджетов доступно:**
- Button
- Checkbutton
- Radiobutton
- Spinbox
- Scrollbar
- Scale

**Использование:**
```python
button = Button(root, text="Click", command=callback)
```

**Особенности:**
- Передаётся **имя функции** без скобок
- Функция-обработчик **не имеет параметров**
- Объединяет разные способы активации (клик мыши, пробел, Enter)

### Метод bind

```python
widget.bind("<событие>", callback)
```

**Синтаксис событий:**
- События указываются в **угловых скобках**: `<Button-1>`, `<Control-Shift-Q>`
- Можно комбинировать модификаторы

**Особенности:**
- Функция-обработчик **должна иметь параметр** `event`
- `event` — объект, содержащий информацию о событии

### Модификаторы событий

**Модификаторы клавиатуры:**
- `Control`, `Shift`, `Alt`, `Meta`
- `Control_L`, `Control_R` — различение левой/правой клавиши
- `Shift_L`, `Shift_R`

**Кнопки мыши:**
- `Button-1` — левая кнопка
- `Button-2` — правая кнопка
- `Button-3` — средняя кнопка
- До 5 кнопок (настраивается в драйвере)

**Кратность нажатия:**
- `Double` — двойной клик (`<Double-Button-1>`)
- `Triple` — тройной клик

**Клавиши с символами:**
- `<KeyPress-a>`, `<KeyRelease-a>`
- `<KeyPress-plus>`

**Специальные клавиши (отдельные слова):**
- `Escape`, `Return`, `space`
- `Home`, `End`
- `Left`, `Up`, `Right`, `Down`
- `F1`...`F12`
- `Num_Lock`

### Объект события (event)

**Атрибуты объекта event:**

| Атрибут | Описание |
|---------|----------|
| `serial` | Уникальный серийный номер события |
| `num` | Номер кнопки мыши (1, 2, 3, 4, 5) |
| `focus` | Имеет ли окно фокус |
| `height`, `width` | Ширина и высота окна |
| `keycode` | Числовой код нажатой клавиши |
| `keysym` | Символ клавиши (строка: `"a"`, `"9"`) |
| `keysym_num` | Символ в виде числа |
| `state` | Состояние события |
| `time` | Временная метка (миллисекунды) |
| `type` | Тип события |
| `widget` | Виджет, инициировавший событие |
| `x`, `y` | Координаты мыши |
| `x_root`, `y_root` | Координаты мыши относительно главного окна |
| `delta` | Скорость вращения колеса мыши |

### Типы событий

| Событие | Описание |
|---------|----------|
| `<Activate>` | Окно активировано |
| `<Deactivate>` | Окно деактивировано (Alt-Tab) |
| `<Button-1>`, `<Button-3>` | Нажатие кнопки мыши |
| `<ButtonRelease-1>` | Отпускание кнопки мыши |
| `<Destroy>` | Уничтожение окна |
| `<Enter>` | Курсор вошёл в виджет |
| `<Leave>` | Курсор покинул виджет |
| `<FocusIn>`, `<FocusOut>` | Получение/потеря фокуса |
| `<KeyPress>`, `<KeyRelease>` | Нажатие/отпускание клавиши |
| `<Motion>` | Движение мыши |
| `<MouseWheel>` | Прокрутка колеса мыши |
| `<Reparent>` | Изменение родительского окна |
| `<Visibility>` | Изменение видимости окна |
| `<Return>` | Нажатие Enter |
| `<Control-z>` | Комбинация Ctrl+Z |

### Привязка событий (bind_all, bind_class)

**Методы привязки:**
- `bind()` — привязка для конкретного виджета
- `bind_all()` — привязка для **всех** виджетов приложения
- `bind_class()` — привязка для всех виджетов **определённого класса** (например, всех `Entry`)

**Методы отвязки:**
- `unbind()` — отвязка конкретного виджета
- `unbind_all()` — отвязка всех обработчиков от всех событий
- `unbind_class()` — отвязка для указанного класса

**Пример использования `bind_all`:**
- Валидация данных для всех текстовых полей
- Глобальные горячие клавиши

## ООП-подход в Tkinter

**Tkinter не требует** определения собственных классов — можно писать процедурно.

**Но для больших приложений** удобно использовать ООП:

```python
class BatPrint:
    def __init__(self):
        self.root = tk.Tk()
        self.bat = Button(self.root, text="Click")
        self.bat.bind("<Button-1>", self.handler)
    
    def handler(self, event):
        print("Hello World")
```

**Преимущества ООП:**
- Удобнее работать с приложением как с объектом
- Легче управлять состоянием (атрибуты)
- Лучшая структура для сложных проектов
