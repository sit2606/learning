## 2. 📌 ДОМАШНЕЕ ЗАДАНИЕ №6: Работа с CSV и почтовыми индексами США
*Это самое объемное задание на данный момент.*

**Исходные данные:**
* Файл `zip_codes_states.csv` (данные по США: 5-значный индекс, широта, долгота, город, штат, округ/county).
* Формат **CSV (Comma-Separated Values)**: данные разделены запятыми. 
  * *Особенности формата:* не имеет единого жесткого стандарта, значения могут быть в кавычках или без, возможны пропуски данных (две запятые подряд, например, при отсутствии координат).
  * Один индекс может обслуживать несколько городов, а в одном большом городе может быть несколько индексов.

**Технические требования к решению:**
1. Считать файл и сохранить данные в структуру (например, список списков).
2. Можно использовать готовый модуль-помощник `ziputil.py` (функция `read_zip_all`), но рекомендуется для практики написать парсинг вручную.
3. Приложение должно иметь консольный интерфейс типа **REPL (Read-Evaluate-Print Loop)**: цикл, в котором программа читает команду, выполняет её и выводит результат.

**Команды приложения:**
* `loc`: найти данные по конкретному почтовому индексу.
* `zip`: найти все индексы по названию города и штата (регистр не важен).
* `dist`: посчитать расстояние между двумя индексами.
* `end`: завершение работы программы.

**Расчет расстояния:**
* Используется **формула Хаверсина (Haversine formula)**. Считает расстояние по дуге поверхности Земли (геоида), а не по прямой сквозь землю.
* ⚠️ **Важно:** Радиус Земли в формуле нужно подставлять в **американских милях**, чтобы результат расстояния также получился в милях.

**Методология разработки (TDD):**
1. Сначала разработать структуру (скелет) приложения с функциями-заглушками (`pass`).
2. Написать спецификации (docstrings) с описанием входных параметров и возвращаемых значений.
3. Написать модульные тесты для каждой функции (рассматривая функции как «черные ящики»).
4. Только после этого писать реальную реализацию кода.
* Избегать глобальных переменных, передавать данные (например, список всех индексов) в функции через параметры.
* Для проверок в коде используется ключевое слово **`assert`** (вызывает аварийное завершение программы с ошибкой `AssertionError`, если условие ложно; может принимать необязательное сообщение об ошибке).

## 4. Обзор среды разработки PyCharm
* Разработчик: компания **JetBrains** (основана выходцами из России/СНГ, создатели IntelliJ IDEA, CLion, WebStorm, языка Kotlin).
* Версии: **Professional** (бесплатно для студентов и преподавателей по академической лицензии) и **Community** (полностью бесплатная, рекомендуемая для базовых задач).
* **Виртуальное окружение (`.venv`)**: PyCharm создает его автоматически при создании проекта, изолируя пакеты проекта.
* **Работа с библиотекой Pillow (создание изображений с нуля):**
  * `Image.new(mode, size)` – создание нового пустого изображения (например, `RGB`, `(500, 500)`).
  * `ImageDraw.Draw(im)` – получение объекта для рисования на изображении.
  * Методы рисования: `line()` (линии), `rectangle()` (прямоугольники, можно задавать `fill` для заливки и `outline` для контура), `text()` (текст).
  * Координаты в графике: начало `(0, 0)` в левом верхнем углу, ось Y направлена вниз.
* **Установка пакетов:** через встроенный терминал (он автоматически активирует `.venv`) или через UI (лампочка-подсказка при импорте, либо *File -> Settings -> Project -> Python Interpreter*).

## 5. Интеграция с Git и управление зависимостями
* **Что НЕ нужно коммитить:** папки виртуального окружения (`.venv`, `venv`) и настройки IDE (`.idea`). Они занимают много места и специфичны для машины разработчика.
* **`.gitignore`**: специальный файл, в который нужно добавить `.venv` и `.idea`, чтобы Git игнорировал эти папки.
* **Проблема зависимостей:** если в коде используется сторонняя библиотека (например, `Pillow`), проверяющий или другой пользователь не узнает об этом, просто глядя на код.
* **Решение:** файл **`requirements.txt`**.
  * Создается командой: `pip freeze > requirements.txt` (или через UI PyCharm: *Tools -> Sync Python Requirements* / *Add imported requirements*).
  * Содержит список пакетов и их версий (например, `Pillow>=10.0`).
  * Позволяет пользователю установить все зависимости одной командой: `pip install -r requirements.txt`.
* **Импорт модулей из других папок:** если модуль лежит вне текущей директории, его путь нужно добавить в список путей поиска интерпретатора: **`sys.path.append('путь_к_папке')`**.

## 6. Альтернативные инструменты: Anaconda и Spyder
* **Anaconda**: популярный дистрибутив Python «всё в одном». Включает в себя сам Python, менеджер пакетов **`conda`**, множество предустановленных библиотек (NumPy, Pandas и др.) и среды разработки. Занимает много места на диске (~1 ГБ+).
* **Spyder**: легковесная среда разработки, входящая в состав Anaconda (можно установить и отдельно). 
  * Не требует создания формальных «проектов» (работает с папками).
  * Имеет удобные панели: редактор кода, интерактивная консоль, просмотр переменных (Variable Explorer), отладчик, профилировщик и окно для графиков (Plots).
  * Отлично подходит для научных вычислений и быстрых примеров.

## 7. Углубленная работа с файлами: запись, чтение и методы строк
**Режимы открытия файлов (модификаторы):**
* `r` (read) – только чтение (по умолчанию).
* `w` (write) – только запись (перезаписывает файл, если он существует; создает новый, если нет).
* `w+` – чтение и запись (перезаписывает файл).
* `a` (append) – добавление в конец файла (создает новый, если не существует).
* `a+` – чтение и добавление в конец.
* `b` (binary) – бинарный режим (например, `rb`, `wb`). Без `b` файл считается текстовым.

**Важность метода `close()`:**
* При записи данные часто попадают не сразу на диск, а в **буфер** оперативной памяти для повышения производительности.
* Если не вызвать `close()` (или не использовать контекстный менеджер `with`), данные из буфера могут быть потеряны при завершении программы.

**Методы работы с файлами:**
* `write(строка)` – записывает строку, возвращает количество записанных символов.
* `writelines(список)` – записывает список строк за один раз.
* `read()` – читает всё содержимое файла в одну большую строку.
* `readline()` – читает одну строку (включая символ новой строки `\n`).
* Итерация по файлу: `for line in file:` – самый эффективный способ построчного чтения.

**Методы строк и преобразования:**
* `strip()`, `rstrip()`, `lstrip()` – удаление пробельных символов (и указанных символов) с концов строки.
* `split(разделитель)` – разбиение строки на список подстрок.
* **`eval()`**: функция, которая принимает строку и выполняет её как питоновское выражение. Позволяет, например, преобразовать строковое представление списка `"['a', 'b']"` обратно в реальный объект списка Python. *(Использовать с осторожностью из-за рисков безопасности при выполнении произвольного кода).*
