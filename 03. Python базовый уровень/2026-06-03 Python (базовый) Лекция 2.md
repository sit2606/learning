## 1. Организационные вопросы и настройка окружения
* **Записи лекций:** Выкладываются не ссылками, а скачанными файлами на Яндекс.Диск по требованию кафедры (чтобы избежать проблем с доступом из облака через Контур).
* **Виртуальные машины для Linux:**
  * *VirtualBox:* Работает нормально, но возможны фризы и проблемы с оптимизацией (особенно на больших/нескольких экранах). Примеры ОС: Ubuntu, Kali Linux.
  * *VMware:* Работает стабильнее и предпочтительнее по ощущениям лектора.
  * *WSL (Windows Subsystem for Linux):* Максимально интегрирован с Windows. Рекомендуется использовать **WSL 2** (WSL 1 устарел и неудачен). Установка через команду `wsl --install Debian`. *Минус:* возможны проблемы с правами доступа к файлам из-за различий файловых систем.
  * *Альтернатива:* Загрузка с флешки (Live USB) или настройка мультизагрузки (Dual Boot) на отдельный раздел диска.

## 2. Сравнение C++ и Python
* **C++:** Код компилируется в исполняемый файл конкретной ОС. 
  * Признак исполняемого файла Windows в HEX-редакторе: **MZ**.
  * Признак исполняемого файла Linux: **ELF**.
  * *Размер файлов:* Исполняемый файл Windows для Hello World (~131 КБ) больше, чем для Linux (~17 КБ), из-за использования **статической линковки** (библиотеки вшиваются в файл) в Windows против **динамической линковки** в Linux.
* **Python:** Язык интерпретируемый. Требует установленного интерпретатора, но обеспечивает высокую переносимость кода (файл `.py` запустится на любой ОС с Python без перекомпиляции).

## 3. Основы Python: переменные, ввод-вывод, типы данных
* **Имена переменных:** Можно использовать кириллицу, но рекомендуется латиница для читаемости кода международными разработчиками.
* **Функции:** `print()` (вывод), `input()` (ввод), `type()` (определение типа).
* **Новое понятие: Динамическая типизация.** Тип переменной не указывается явно и не фиксируется. Он определяется автоматически по присваиваемому значению и может меняться в процессе выполнения программы (в отличие от статической типизации в C++/C#).
* **Преобразование типов:** Функция `input()` всегда возвращает строку (`str`). Для математических операций необходимо явное преобразование, например, с помощью функции `int()`.
* **Новое понятие: Конкатенация.** Операция объединения строк с помощью оператора `+`. Это не сложение, а именно склеивание. Для конкатенации все числовые значения должны быть предварительно преобразованы в строку через `str()`.
* Функция `input()` может принимать строковый параметр-подсказку: `input("Введите значение: ")`.

## 4. Условные операторы и форматирование кода
* **Новое понятие: Булевский (логический) тип данных (`bool`).** Имеет только два значения: `True` (истина) или `False` (ложь). Используется как результат сравнений и условие для ветвления.
* **Условный оператор `if` / `else`:** 
  * В Python после условия ставится двоеточие `:`.
  * **Новое понятие: Отступы (Indentation).** Блок кода, относящийся к условию, выделяется отступом (символ табуляции или пробелы). Количество пробелов не строго фиксировано, но должно быть консистентным.
  * *Рекомендация:* Использовать продвинутые редакторы (например, Notepad++), которые визуально отображают пробелы и табуляцию и автоматически расставляют отступы для `.py` файлов. Стандартный Windows Notepad не рекомендуется.
* **Сокращенная запись операций:** Вместо `speed = speed * 2` можно и нужно писать `speed *= 2`. Аналогично для `+=`, `-=`, `/=`.
* **Деление:** 
  * Обычное деление `/` всегда возвращает тип `float` (даже если результат целый).
  * **Новое понятие: Целочисленное деление `//`.** Возвращает целое число, при этом дробная часть не округляется, а просто отбрасывается (усекается).

## 5. Математические операции и модуль `math`
* **Возведение в степень:** Оператор `**` (две звездочки). Пример: `2 ** 10` (1024). Операция является правоассоциативной.
* **Извлечение корня:** Это частный случай возведения в степень. Квадратный корень из `x` равен `x ** 0.5`.
* **Новое понятие: Модуль (библиотека) `math`.** Для тригонометрии и продвинутой математики нужно подключить модуль командой `import math`.
  * Использование: `math.pi`, `math.sin(угол_в_радианах)`.
  * *Важно:* Тригонометрические функции в Python принимают аргументы в радианах. Градусы необходимо предварительно переводить в радианы.

## 6. Форматированный вывод
* **Новое понятие: Форматные строки (f-строки).** Строка с префиксом `f` или `F` перед открывающей кавычкой (например, `f"Значение: {x}"`).
* Позволяет встраивать выражения и переменные прямо в строку внутри фигурных скобок `{}`.
* **Форматирование чисел:** Внутри фигурных скобок можно указать формат вывода. Например, `{value:.4f}` выведет число с плавающей точкой, округленное до 4 знаков после запятой *только при отображении* (само значение в переменной не меняется).
* Python полностью поддерживает Unicode, поэтому в коде и выводе можно использовать греческие буквы (например, `π`) и другие алфавиты.

## 7. Теория и практика тестирования программного кода
* **Проблема тестирования:** Невозможно протестировать все комбинации входных данных (комбинаторный взрыв). Даже миллионы успешных тестов не гарантируют отсутствия ошибок.
* **Новое понятие: Верифицирующие компиляторы.** Альтернатива тестированию. Подход, при котором компилятор математически доказывает правильность кода как теорему, без его запуска. Пока применим только к относительно простым проектам, но активно развивается.
* **Цель тестирования:** Не доказать правильность кода (это невозможно), а найти как можно больше ошибок.
* **Автоматизация тестирования (Редирект ввода-вывода):** Ручной ввод данных утомителен и подвержен ошибкам. Следует использовать перенаправление потоков операционной системы.
  * **PowerShell (Windows):** 
    * Ввод из файла: `Get-Content input.txt | python script.py`
    * Вывод в файл: `python script.py > output.txt`
  * **Command Prompt (Windows) / Bash / Zsh (macOS/Linux):**
    * Ввод из файла: `python script.py < input.txt`
    * Вывод в файл: `python script.py > output.txt`
* **Сравнение результатов:** Использовать инструменты сравнения файлов (WinMerge, Meld в Windows; `diff` в Linux/macOS) для сопоставления файла с реальным выводом (`actual output`) и файлом с ожидаемым выводом (`expected output`).
* **Золотое правило тестирования:** Ожидаемый результат (`expected output`) должен быть рассчитан **независимым способом** (вручную по формулам, через доверенный калькулятор или эталонную программу), а не взят из вывода тестируемой программы, которая может содержать ошибки.

## 8. Методы отладки и поиска ошибок
* Если итоговый результат не совпадает с ожидаемым, необходимо выводить **промежуточные значения** переменных (например, $x$, $l_1$, $l_2$, $t$ в задаче про спасателя).
* Сравнивая промежуточные вычисления программы с ручными расчетами, можно точно локализовать строку или формулу, в которой закралась ошибка.
